The latency measurements in [SYNC.md](SYNC.md) are MEASURED but do not determine a B parameter. Cross-host transport, task-channel continuity, optional social actions and cloud deployment are outside this milestone. New implementation discoveries that would change these approved user-facing behaviors must be recorded here rather than silently changing the protocol.

B implementation details under delegated discretion:

* Norms edit summaries are capped at 500 characters; private follow overrides at 256 per participant. Both give an actionable limit error without discarding a draft.
* New follows begin at the saved arrival boundary. Inbox and wake boundaries are separate; modifying a mute preserves an existing follow. Removing an override restores inherited behavior.
* Participant norms acknowledgement, monitor definitions/results boundaries, preferences, and private operation receipts share one atomic participant-state file under `_state/participants/`. Monitor hits are reconstructed from an immutable predicate and retained arrival interval, not an unbounded hit-ID array.
* Transcript verification reads at most 2 MiB per tick and restarts its coverage when the file version changes. Incomplete, malformed, oversized, truncated or changed original bindings cannot authorize a retry. A positive marker must be in a recognized incoming Claude/Codex record in the current binding. A legacy A attempt without an original binding remains conservative about retries.
* An enabled Owner bell uses an atomic at-most-once claim. Enabling it starts with the current activity boundary; a lost claim response can miss a bell, but cannot duplicate one after restart. Messages, passive badges and monitor hits remain readable.
* Native Owner forms save drafts locally. `W` creates a monitor from a conversation, `f` opens its preferences, and `R` retries an unresolved operation with its saved origin/request ID. Norms publishing requires a user-invoked diff preview; a conflict preserves the draft and explicit rebasing selects the new base.

## Post-B Owner feedback, September 7

Owner requested one chronological full-message pane with j/k selection, subtle unread markers and stronger DM/mention markers, an expandable DM section containing only started conversations, recipient search, and group DMs. This supersedes row 3's two-member-only scope. Groups reuse the existing immutable member-list descriptor; the implementation bounds them at 32 members, starts them on first send, and never adds recipients to an existing conversation. Monitor/follow scopes keep pair DMs separate from groups. The picker uses Tab for multiple recipients, leaving ordinary typed letters available for search.
