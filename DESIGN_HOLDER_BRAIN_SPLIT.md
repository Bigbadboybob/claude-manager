# Holder/brain process split — design proposal (phase 0)

Branch: `cm/holder-brain-daemon-process-split-crash-class-rest` (branched from `cm/fix-cm`, which carries the seamless-restart stack this design builds on; implementation phases land on their own branches)

Status: **revised after adversarial review rounds 1 and 2** (2026-08-18 — two independent round-1 reviews, then a round-2 verification pass whose nine edits are folded in as V1–V9; see Review log). The architecture survived review; the original spec did not. The load-bearing changes: session env is fully composed brain-side and the holder `env_clear`s (the original "spec-only env" claim was false against portable-pty's inherit-by-default, S1); brain-side sessions carry **no kill-on-drop authority** (S2); the holder's channel IO is strictly nonblocking with brain-not-draining counted as a wedge (S3); reaping is authorization-gated per session (`arm_reap`, the protocol descendant of the reap gate) so the fast-exit race and the forget-zombie leak are closed (S4/O6); exit identity is a holder-minted **incarnation id**, never the brain's transcript `generation` (O2); the breaker/hold-down machine is fully specified with a path-retry recovery input (O1/O5); listeners are **brain-bound, holder-custodied** (O11); and the migration writes a fresh rollback manifest and carries the parked brain's pidfd (S5).

Implementation is **double-gated** and neither gate is open as of 2026-08-18:

1. **Re-exec must ship first.** DESIGN_SEAMLESS_RESTART phases 4–6 (full rehydrate, TUI auto-reattach, `daemon.restart` RPC) must be complete and deployed. As of this draft, `cm/fix-cm` is at phase 3b (`4e109b3`) with phase 4 in progress. Re-exec is the on-ramp: its artifacts are reused wholesale (§ Reused artifacts) and its exec machinery IS the migration vehicle (§ Live migration).
2. **Crash-class survivability must be an actual requirement.** Objective trigger (O18e): a crash-class failure (segfault / OOM / abort / uncaught exit) has actually killed hosted sessions in production at least once *after* re-exec shipped, or the operator adopts an explicit session-survival SLO that re-exec's residual cannot meet. Re-exec already survives every deploy of a working binary and every recoverable rehydrate failure; this split exists solely to remove re-exec's structural residual (review finding R1). Until the trigger fires, this design stays on the shelf.

## Trigger and goal

DESIGN_SEAMLESS_RESTART's Goal section, verbatim: "A **crash-class** failure in the new image — segfault, abort, OOM-kill, panic-with-abort, an uncaught early exit — cannot execute any rollback path: the process dies, the PTY masters and listener close with it, and the children are lost. … it cannot be engineered away inside a single process. If unconditional survival of a bad binary ever becomes a requirement, the holder/brain split stops being optional."

This document is that split. The structural observation (same doc, "Why this exists"): **the code that churns is brain-level** (auth, RPC, monitors, workflows, config, policy) **while the PTY layer it shares a process with is stable and owns the durable things** (child processes, master FDs). The split puts the durable things in a process that never changes:

- **cm-holder** — tiny, near-frozen, single-threaded. Parent of every session child and of the brain. Owns: fork/exec of session children, the canonical PTY master FDs, the spawn-time pidfds, exit reaping (`waitid` is parent-only — the one duty that *cannot* live anywhere else), kill-attribution echo, custody of the control-socket listener FDs, and supervision of the brain (respawn with backoff + one-deep pinned-binary rollback + a path-retry recovery input).
- **cm-daemon (the brain)** — everything else, i.e. today's daemon minus the fork/exec+reap innards. Restarts freely; crashes freely. On every start it re-adopts the live sessions from the holder over an inherited socketpair via SCM_RIGHTS FD passing, using the same non-killing adoption path re-exec built (`adopt::SessionCandidate` → `DaemonSession::adopt`), with **inert-Drop** session objects (§ Kill authority).

Headline properties the split buys (none of which re-exec can provide):

| Property | Mechanism |
|---|---|
| A crashing brain kills no session | Holder keeps canonical masters + pidfds; brain-side session objects cannot signal on Drop (§ Kill authority); brain respawned by holder |
| A brain deploy that segfaults on start **rolls back automatically** | Holder keeps a one-deep pinned-FD history of brain binaries; the breaker (§ Supervision) execs the previous pin; hold-down re-pins from the on-disk path so a fixed binary self-heals (O1) |
| Double-brain / double-reader is structurally excluded | Inherited socketpair (no named socket); holder spawns the next brain only after the previous brain *process* has exited; plus the mandatory FD-hygiene rules of § The channel (S10 — kernel guarantee *and* stated discipline, not either alone) |
| Exit statuses survive brain downtime | Holder consumes `waitid(P_PIDFD)` under per-session authorization (`arm_reap`), queues exit events (bounded by live sessions — overflow structurally impossible), redelivers until acked |
| Kill attribution survives brain death | Attribution rides in the `signal` verb and is echoed back in the exit event — the holder remembers who asked even if the asker died; routing rule in § Exit provenance (O4) |

## Out of scope

- **Machine reboots** — children die with the machine; startup-restore + H1-pinned resume stays the answer.
- **TUI-owned session rows** (`DaemonState::tui_sessions` snapshots) — TUI-process-resident PTYs never survived daemon restarts and are untouched here.
- **Holder crash survivability.** The holder crashing is exactly today's daemon crash: every PTY dies. The mitigation is frozenness (small, single-threaded, no policy, near-zero churn) plus OOM posture (§ Supervision), not another layer of indirection. Stated as the design's honest residual, the way R1 was for re-exec.
- **Multi-host / remote transport changes.** `hosts.toml`, ssh tunnels, TUI attach — all talk to the control socket, which the brain serves exactly as today.
- **The MCP server, planning API, dispatch/cloud lane** — untouched; they speak to the control socket.

## Environment composition (S1)

portable-pty's `CommandBuilder::new` snapshots the **constructing process's** environ (`get_base_env()`; applied via `env_clear` + re-apply in `as_command`). Today's "composed env" is therefore CM_\* deltas over the daemon's inherited environment — PATH, HOME, SHELL, TERM, LANG, `XDG_RUNTIME_DIR`, `DBUS_SESSION_BUS_ADDRESS` all reach sessions only by daemon-environ inheritance, and `systemd-run --user` depends on exactly those. The original draft's "session env comes fully from the spawn spec" was false as stated. The corrected contract:

- **The brain composes a *complete* environment** into every spawn spec: a snapshot of the brain's own post-`env_sanitize` environ (the brain runs `scrub_inherited_session_env()` at startup as today, `lib.rs:319`), overlaid with the per-session CM_\* composition (`methods.rs:627-731`) and the existing secret scrubs (`session.rs:1414-1450`, relocated into spec composition).
- **The holder applies the spec exactly**: `CommandBuilder` + `env_clear()` + set precisely the spec's map. The holder's environ reaches **no session, ever** — it is not a default, not a base layer, nothing.
- The brain's environ is inherited from the holder (the holder spawns it), which inherited from systemd/the TUI — so the effective base is the same as today's daemon environ, sanitized at each brain start. A holder launched from inside a hosted claude session (the 2026-08-18 incident class) carries the poison in *its* environ for its lifetime, but every brain generation scrubs before composing, and the holder's environ never reaches a session — the leak class stays closed without the holder running scrub logic itself.
- Guard test: a canary var set in the holder's environ (and NOT in the spec) must be absent from a spawned session's `/proc/<pid>/environ`.

## Kill authority (S2)

`DaemonSession::Drop` today SIGKILLs its child via pidfd (`session.rs:2834`), and `pidfd_send_signal` works from any same-UID dup-holder — so a brain that adopts the fleet and then fails during its own startup (bind error, config error, panic-unwind reaching the registry) would SIGKILL every child the split exists to protect. Therefore, structurally:

- **Brain-side session objects have no kill-on-drop.** In split mode, `DaemonSession`'s Drop closes fds and touches nothing else — the `SessionCandidate` property (`adopt.rs`: "drop closes its own fds and never signals") extends through promotion for the session's whole brain-side life. A brain crash or unwind, at any point, closes dups and nothing more.
- **Kills are verb-only.** Every deliberate kill path — `kill_session`, the `mark_subtask_done` sweep, drain/shutdown kills, workflow fresh-context respawns, spawn-failure aborts — routes the holder (`signal` / `abort_spawn`). `DaemonSession::kill()` becomes a client call, not a syscall.
- The brain's pidfd dup exists for **observation only**: exit-ready polling (`poll_pidfd_until_exit_ready` works from a non-parent) and identity cross-checks. A source-scan guard test (the repo's guard-test idiom) asserts no brain-side `pidfd_send_signal`/`kill(2)` call sites against session pidfds outside the holder client. (The memory-cap watcher's victim kills target arbitrary in-cgroup PIDs — usually grandchildren the holder has no record of — and stay brain-direct; see § Watcher placement.)

This is a real semantic change to `DaemonSession::adopt` (whose contract today says adopted sessions get "the pidfd-SIGKILL Drop"); the split does not reuse that clause, and the doc for the type gains a split-mode paragraph in phase 3.

## The holder

A single-threaded event loop over `poll(2)`: the brain socketpair end, one pidfd per session child, the brain's pidfd, and a timerfd (watchdog/backoff timers). No threads, no async runtime, no state lock — there is nothing to lock. An exit-ready pidfd of an **un-armed** record is masked out of the poll set with its readiness latched (V7 — an exited child's pidfd is level-triggered readable and would otherwise spin the loop at 100% CPU during the spawn-to-arm window); `arm_reap` unmasks it straight into the `waitid` path.

**Nonblocking IO, mandatorily (S3).** The channel is `O_NONBLOCK` in both directions holder-side, with a bounded in-holder outbound queue. The holder never issues a blocking `write()` — a brain whose channel-consumer stops draining (state-lock convoy, wedged persist) would otherwise wedge the *holder's* loop, including the very watchdog meant to catch it. Rule: outbound queue full beyond a threshold for longer than the wedge horizon ⇒ the brain **is** wedged (same consequence as missed pongs: SIGKILL + respawn + breaker strike). The loop's only other latency is `spawn`'s fork/exec round-trip — bounded milliseconds, stated as the loop's latency budget.

**Holder-resident state, in full** (per session): `{uid, incarnation, generation_meta, child_pid, child_start_time, canonical_master: OwnedFd, canonical_pidfd: OwnedFd, reap_armed: bool, cgroup_prefix: Option<String>, cgroup_path: Option<String> (set at arm, V5), watcher_checkpoint: Option<serde_json::Value>, last_signal_request: Option<{sig, attribution, at}>, spawned_at}` — a superset-compatible sibling of `reexec_manifest::SessionRecord` (`reexec_manifest.rs:185`), because the migration writes one into the other (§ Live migration). **`incarnation` is a holder-minted monotonic u64, and it — never the brain's `generation` — keys every verb and event** (O2: `generation` in this codebase is the transcript-rotation counter, bumped by /clear//compact and *reused* across revive — the exact wrong identity; it rides the record as opaque `generation_meta` for the brain's benefit only. The `reexec_manifest.rs:188` doc-comment calling it "monotonic across revives" is drift to fix in re-exec phase 4). Plus: the exit-event queue (bounded by live sessions — a session exits at most once per incarnation, so overflow is structurally impossible; the original draft's lossy-ring language is deleted, S12/O7), custodied listener FDs (§ Listeners), the current + previous pinned brain-binary FDs + the `--brain` path for hold-down re-pinning (O1), the brain's pid/pidfd/socketpair/`epoch`, and the breaker state (§ Supervision). **`epoch`** (O18c) is the holder's brain-spawn counter — it names the brain generation in `hello`, `status`, and logs. The holder persists **nothing to disk** except its own log; all durable state is brain-side. If the holder dies, everything dies — disk-durability inside the holder buys nothing.

**What the holder must never contain** (the frozenness contract, enforceable at review time): config parsing beyond argv, the control wire protocol, auth of any kind, JSON-RPC dispatch, planning/API clients, transcript or task or workflow or workspace concepts, policy of any kind (cap sizes, protected sets, idle rules, victim selection), PTY byte handling, socket binding, disk persistence. One narrow carve-out, explicit (S6): at `waitid` time, if the record has a stored cgroup path (delivered on `arm_reap`, V5), the holder does a single best-effort read of `<path>/memory.events` into the exit event — a mechanical file read, no interpretation. A holder change is a design-doc-noted event that must run the full skew matrix (§ Version-skew testing). LOC budget: ~1,500–2,500 including the protocol server side.

**Dependencies**: `libc`, `nix`, `portable-pty` (spawn parity — see below), `serde`/`serde_json` (protocol + manifest payloads), `sha2` (sealed-manifest checksum on the migration path). No `anyhow`, no `toml`, no clients.

**Spawn parity**: the holder spawns via `portable_pty::native_pty_system().openpty(...)` + `slave.spawn_command(...)` — the exact primitive `PendingSession::spawn` uses today (`session.rs:1394-1495`) — then extracts and keeps the raw master fd and pidfd. Reusing the battle-tested path keeps child-side semantics (session leader, controlling tty, slave closed in parent, `close_random_fds` in the child pre-exec — verified: portable-pty's own pre_exec scrubs fds > 2, so holder-fd hygiene toward sessions is structurally covered) bit-identical to today. portable-pty's `Child` is a bare `std::process::Child` whose Drop neither kills nor waits (verified against the vendored source) — the holder drops it and owns the child via pidfd alone, as today's reaper does. `openpty`/`spawn_command` spawn no helper threads — compatible with the single-threaded loop.

**Bootstrap**: argv only — `cm-holder --brain <path> --log-file <path>`; on the migration path, `CM_REEXEC_MANIFEST_FD` (validated by the same sealed-memfd code, then scrubbed). No `--socket-path`, no `--tls`: the holder binds nothing (§ Listeners). `setrlimit(NOFILE, 65536)` at start (2 FDs per session × `MAX_SESSIONS` 4096 ≈ 8k, plus headroom); **the brain raises its own NOFILE equally at startup** (O15 — it holds 2+ dups per session plus its normal load).

## The channel: an inherited socketpair, never a named socket

The holder⇄brain channel is a `socketpair(AF_UNIX, SOCK_STREAM)` created by whoever spawns the brain, with one end inherited by the brain as a known FD. There is **no named holder socket on the filesystem, ever**. Consequences:

- **Unforgeable.** Hosted sessions run as the same UID; a named 0600 holder socket would hand every hosted agent a spawn-arbitrary-argv / signal-any-session / take-any-session's-FDs surface, gated only by another token scheme. An inherited socketpair has no path to connect to — the attack surface does not exist.
- **Exactly one brain — kernel guarantee *plus* stated discipline (S10).** The holder spawns the next brain only after `waitid` on the previous brain's pidfd returns, and **closes its old socketpair end at that moment** (killing any SCM_RIGHTS dups still in flight inside the dead channel's buffer). Process exit closes every FD the old brain itself held. The residual channel: FDs a brain-forked *transient* child (git, python preflight) inherited and outlived the brain with. Closing that channel is brain-side protocol law: **every SCM_RIGHTS receive uses `MSG_CMSG_CLOEXEC`**, and every brain-held session/listener/channel FD is CLOEXEC from birth (`F_DUPFD_CLOEXEC` throughout, as today's `session.rs:2593` / `adopt.rs` already do). With those two rules — enforced by a proto-crate scan test and a skew-suite canary — an orphaned transient child can hold no session FD, and double-reader is excluded.
- **Survives the migration exec.** During live migration the *brain exists before the holder* (§ Live migration): the old daemon creates the socketpair, spawns the brain with one end, and carries the other end across its own exec into the holder image via the re-exec manifest. A socketpair end is just an FD; the manifest already knows how to escort FDs across an exec.

**Framing and SCM_RIGHTS law (O15)**: length-prefixed JSON frames. FD-bearing frames follow strict conventions, each with a skew-suite test: (1) one `sendmsg` per FD-bearing frame, ancillary data attached to that frame's first byte, never coalesced with other frames' bytes in the same `sendmsg`; (2) receivers always supply a control buffer sized for the frame type's declared FD count (max 2) and always pass `MSG_CMSG_CLOEXEC`; (3) a frame that promises FDs arriving without them, or with `MSG_CTRUNC` — protocol violation: the brain treats it as fatal and exits (respawn is cheap and safe); the holder treats it as a brain failure (close channel, SIGKILL, breaker strike); (4) unexpected FDs on a non-FD frame are closed immediately, never stored.

**Version negotiation**: the brain always sends first — `hello {proto_min, proto_max, brain_build_id}`; the holder replies `{proto: chosen, holder_build_id, holder_proto_min, holder_proto_max, epoch, session_count}` (no deadlock: writer roles are fixed, and both sides' first read is bounded by a handshake timeout; the parked migration brain's first read is instead bounded by O14's 60s adopt deadline, which supersedes the generic timeout — its hello reply legitimately waits out the monolith's manifest-build + exec + validation, V8). No overlap → brain logs loudly and exits with a distinct code the holder recognizes as `proto_mismatch` (counts toward the breaker → previous-pin rollback, which is only *usually* sufficient — see the S15 gate in § Holder upgrades). Within a major version: unknown JSON fields are ignored on both sides (`deny_unknown_fields` is banned in the proto crate — enforced by a source-scan test); an unknown verb gets a typed `unsupported_verb` reply, never a disconnect.

### Why write / resize / read are NOT verbs

The task sketch listed `write`/`resize` in the holder's verb set. This design deliberately removes them: the brain receives master-FD **dups** at spawn/adopt and performs PTY reads (`gated_reader_loop` on a further `F_DUPFD_CLOEXEC` dup, exactly as today), writes (`SessionWriter` writes on the dup; `write_and_stamp_operator`, prompt-delivery threads — all unchanged), and resizes (`TIOCSWINSZ` acts on the terminal; any fd of the master works) directly. Because:

- **The data plane must not cross the IPC boundary.** Attach streams shovel PTY bytes at interactive rates; verb-mediating them doubles copies, adds a hop of latency to every keystroke, and — worst — makes the holder protocol *hot*: a busy, high-frequency surface is exactly what accumulates churn pressure, and holder churn is the one thing this design must prevent. With dups, the holder's steady-state message rate is ~zero (exit events + rare checkpoints + 30s pings).
- **It's already proven.** `AdoptedMasterPty` (`adopt.rs:105`) runs the full `MasterPty` surface honestly over a bare inherited fd — including the writer-drop-VEOF suppression and on-demand `tty_name` (review-verified, incl. EIO→EOF on a master dup after child exit and `TIOCSWINSZ`-on-dup). Re-exec's rehydrate already runs sessions on adopted fds; the split makes adoption the *only* path.
- **Crash semantics are exactly right for free.** Brain dies → its dups close → the canonical master in the holder keeps the PTY's open file description alive (no SIGHUP to the child — review-verified); nobody reads → the kernel buffer (~64 KiB) fills → a chatty child blocks on write. A stall, never loss. The new brain adopts and its readers drain the backlog.

The one write-path caveat: a brain that dies **mid-`write_all`** of a multi-byte paste leaves a partial prompt in the child's input buffer — the R10 problem, now unfixable-by-barrier for *crashes* (planned restarts still quiesce writers via the coordinator). Honest position: a crash-class brain failure can leave one session with a half-typed prompt (visible, recoverable by a human or by the respawned brain's delivery verification); it cannot corrupt state or lose the session. Recorded in the failure table.

### Spawn path, before/after

Today's `start_session_with_spawn_fn` ordering (`methods.rs:444`) survives with one substitution. Brain-side, unchanged: cap validation, workspace resolve, worktree serialization queues, `claude_trust::maybe_pretrust_for_spawn` (a `~/.claude.json` write — happens before the verb), kill-log baseline capture (`reaper::capture_baseline_for_spawn`), argv composition including the `systemd-run` wrap, and now *full* env composition (§ Environment). Then, instead of `PendingSession::spawn` forking in-process: the `spawn` verb → holder forks → reply `{incarnation, pid, child_start_time}` + 2 dups → brain builds a `SessionCandidate` from the dups → cgroup discovery from `/proc/<pid>/cgroup` (`path::discover_session_cgroup_path` — plain /proc reads, valid even for a fast-exited child because the un-armed holder holds it as a zombie), watcher spawn, then the existing lock-held tail: uid recheck → promote → `DaemonSession::adopt` (inert-Drop variant, § Kill authority; arms the brain-side reader + exit observer) → registry insert → **`arm_reap`** → persist → `ManifestDiff::Added`. Failure anywhere pre-insert → `abort_spawn`. **Spawn and crash-recovery become the same code path** — every brain-side session is an adopted session.

Reconciliation seams (S4): a brain that dies between the holder's fork and its own persist leaves a holder record the next brain's snapshot lacks → adopted as `orphan_adopted` (operator disposes; sessions are user-owned, never auto-killed). A retried spawn hitting `uid_exists{incarnation}` resolves against that record: adopt it or `abort_spawn` it, explicitly — never spawn a twin.

The brain-side "reaper" thread becomes an **exit observer**: the pidfd-poll half of `gated_reaper_body` (`poll_pidfd_until_exit_ready`) is unchanged — pidfd polling works from a non-parent — but the consume step (`consume_exit_status`'s `waitid`, parent-only, would `ECHILD`) is replaced by "await the holder's `exit_event` for authoritative status". The reap gate (`reap_gate.rs`) is succeeded by `arm_reap` + the ack protocol for brain restarts (an unacked status is redelivered, never lost) and remains only inside the holder's own re-exec path (§ Holder upgrades).

## Listeners: brain binds, holder custodies (O11)

The holder must hold listener FDs across brain restarts (no connection-refused window) — but binding is policy-adjacent (stale-socket probe, atomic-0600 umask dance in `lib.rs:177/:273`, `[tls]` config in `daemon.toml`) and belongs in the brain. Resolution: **the brain performs every bind; the holder is a custodian.**

- Fresh start: holder boots with no listeners; the first brain binds the Unix socket (existing `bind_socket`, unchanged, in the daemon crate) and the TLS listener when configured, then `store_listener`s each FD with the holder. The socket file appears when the first brain is up — the TUI's launch probe already polls with a timeout.
- Brain restart: `adopt_listeners` returns dups of the custodied FDs; the brain skips binding. `SO_REUSE`-style races are impossible — the listening socket is the same open file description across generations.
- Rebind (config change): brain binds the new, `store_listener`s it (holder closes the old after the swap), so `daemon.reload_config` can rebind TLS — impossible under the original holder-binds draft.
- Shutdown: the holder unlinks the stored Unix socket path (from `store_listener.meta`) on exit, best-effort; the next bind's stale-probe still covers a crash.
- Diagnostics honesty (S14/O12): during a brain gap, `connect()` on the custodied listener **succeeds into the backlog and hangs** — it does not refuse. Clients (TUI, MCP, health probes) must use connect+request timeouts and treat them as "daemon unhealthy", not "daemon absent"; the TUI change is specified in § Supervision.

## Exit provenance over IPC

The fidelity requirement: today's tombstone/attribution semantics (`handle_session_exit`, `methods.rs:1125`) must survive the boundary — `killed`/`killed_by`/`exited_at` on tombstones, `memory_cap_kill` classification, `status="reported"` carry-over, monitor fire messages quoting kill provenance.

- **The kernel status** (`code`, `signal`) is consumed by the holder at `waitid` time and stamped with the holder's clock (`exited_at` fidelity across brain downtime — the brain uses the event's timestamp, not its receipt time).
- **Attribution routing rule (O4), explicit:** every kill that records attribution today — `kill_session` (`methods.rs:1690`, `"operator"`/caller uid), the `mark_subtask_done` sweep (`methods.rs:13968`, `"<uid> (mark_subtask_done)"`), drain/shutdown kills — **must route the `signal` verb**; a guard test asserts no attributed kill path signals a session pidfd directly. Echo-less by design: `abort_spawn` (pre-registry, nothing to attribute) and inert Drop (signals nothing, § Kill authority). The brain keeps `DaemonState::record_kill_request` exactly as today *and* the holder echoes `last_signal_request` in the exit event, so `handle_session_exit`'s merge gains one source: explicit kill request (brain state) → holder echo (survives brain death) → memory-cap classification → unattributed. A brain that died between `kill_session` and the exit event no longer loses the `killed_by` — strictly better than today.
- **`LastExitProbe` correlation is unchanged in shape**: `set_kernel` is fed by the exit-event consumer instead of an in-process reaper; the lazy consume-time kill-log scan (`reaper::build_last_exit_since` against the spawn-time baseline) still classifies watcher kills. The attach `End` frame's bounded spin on `kernel_set` (`stream.rs:543`) still closes the reader-EOF-vs-status race — now reader-EOF (brain) vs exit-event arrival (holder), same ≤1s bound, same degradation shape (review-verified).
- **Cap kills during brain downtime (S6), honestly:** the kernel enforces the hard cap regardless (`MemoryMax` lives in the cgroup), but `is_cap_kill` (`reaper.rs:119`) returns false without a kill-log record, and the dead brain wrote none; the scope's `memory.events` is torn down with the scope. Mitigation: the holder's carve-out `memory_events_snapshot` read at `waitid` time (best-effort — it can lose the teardown race), which the brain's classifier accepts as cap evidence (new, additive input to the existing lazy classification). **Residual, named:** a hard-cap OOM kill during a brain gap whose snapshot read lost the race is tombstoned as a natural signal-9 exit — the truncated-tail-as-final-report UX bug can recur in exactly that window. Accepted; the alternative (a policy-bearing holder) costs more than the window is worth.
- **Exit events are bounded by live sessions** (one per incarnation), so the queue cannot overflow; the original lossy-ring semantics are deleted (S12/O7). The one residual "no status" case — a brain snapshot names a session the holder has neither a record nor an event for (e.g. holder restarted via upgrade while the session was already `forget`-eligible) — tombstones as `status_lost: true` with `killed=false`, no code/signal, `exited_at` = detection time: a new honest tombstone field, surfaced like `killed` is today.

## Memory-cap watcher placement

**Decision: the watcher loop stays brain-side; its policy state checkpoints into the holder.** The `SessionRecord.watcher_checkpoint` placeholder (`reexec_manifest.rs:215`, reserved by R12 for exactly this) becomes live: `{protected: [(pid, starttime)...], last_high, kills_file_offset_baseline}` — protected entries are **(pid, starttime) pairs**, not bare PIDs (S13: bare PIDs are recycling-unsafe across a checkpoint's lifetime; the R6 idiom, `adopt.rs` `proc_starttime`, upgrades the live watcher too while the shape is being defined). Written via `update_checkpoint` when it changes — rare (protected-set finalization once at spawn+2.75s; `last_high` per breach). A respawned brain re-adopts and resumes the same policy instead of recomputing from the live cgroup — recomputing would rebuild `protected` from *current* `cgroup.procs`, which after a runaway fork would protect the very hog the cap exists to kill.

During brain downtime there is **no soft-cap enforcement** (no watcher); the kernel-enforced hard cap is the backstop, and the attribution residual for that window is stated in § Exit provenance. The watcher's victim kills (highest-RSS non-protected in-cgroup PID — usually a grandchild the holder has no record of) remain brain-direct signals with their own starttime+cgroup re-verification (`session_watch.rs` `mod kill`), outside the holder verb set by design.

**Capability probing must cross the boundary (S8):** `mcp_config::user_scope_capable` today runs `systemd-run --user --scope … /bin/true` *in the daemon's own context*; post-split the real capped spawns run `systemd-run` from the **holder** with spec-composed env. The probe therefore becomes a `spawn` verb of the same probe argv through the holder at brain startup (cached per brain generation, as today per process) — otherwise the probe validates the wrong environment and re-opens the flaky spawn-then-SIGKILL class it exists to close.

**Alternative considered and rejected — holder-side enforcement loop**: moving `run_watcher`'s poll/breach/kill loop into the holder keeps soft-cap enforcement alive during brain downtime. Rejected because it moves policy (victim selection, protected-set semantics, grace timing, kill-record shape — `session_watch.rs` is 1,900 lines with three behavioral revisions) into the frozen process, for a window the kernel hard cap already bounds. If soft-cap-during-outage ever matters, the verb surface admits it later (`install_watch {spec}`) — additive, per the protocol rules.

## Supervision topology

**One external supervisor, one supervised binary: the holder.** systemd on cm-manager (`cm-daemon.service`'s `ExecStart` becomes `/opt/cm-daemon/cm-holder --brain /opt/cm-daemon/cm-daemon`, `Restart=always` now guarding only holder crashes); the TUI locally. **The brain is never a systemd unit and never TUI-launched** — the holder is its parent, always.

**Brain lifecycle and the breaker (O1/O5/O9), fully specified.** The holder pins brain binaries by FD at exec time (`open` + `fexecve`, R7 — a mid-deploy `cp` can never half-apply) and keeps `{current, previous}` pins plus the `--brain` *path*. States:

| State | In it because | Exits it via |
|---|---|---|
| `RUNNING` | brain alive, hello'd | brain exit → `BACKOFF`; `restart_brain`/`rollback_brain` → exec next/previous pin |
| `BACKOFF` | brain exited | respawn current pin after backoff (0.5s → 30s cap). **Crash counter**: trips → `ROLLBACK` at 3 *consecutive* exits with no intervening stable run — deliberately un-windowed (V1: a 60s window never trips on a slow loop crashing every minute or two, which would flap forever); a **stable run** (10 min with hello + adopt completed + no exit) resets the counter |
| `ROLLBACK` | breaker tripped | exec the **previous** pin; the failed pin is **discarded, not demoted** — the pair cannot ping-pong (O5). No previous pin (first post-migration brain, or already consumed) → `HELD_DOWN`. Previous also trips the breaker → `HELD_DOWN` |
| `HELD_DOWN` | no pin works | every 60s: **re-open `--brain` from the path, fresh pin, try it** (O1) — an operator who fixes the binary on disk self-heals the fleet with no channel and no signal; `SIGUSR2` forces an immediate retry. Each attempt logged. Sessions ride it out indefinitely (they stall at worst) |

Environmental crash loops (corrupt `daemon-sessions.json`, API down at boot) crash *both* pins — the path-retry input is what makes `HELD_DOWN` recoverable without killing the holder, which was the original spec's only exit (O1: committing the exact fleet-kill the design exists to prevent).

- **Wedge watchdog**: `ping` every 30s; 3 misses (90s) → SIGKILL the brain, respawn, breaker strike. `pong` is lock-free by spec (S9); outbound-queue-not-draining is the same wedge (S3). The lock-free pong deliberately leaves one class invisible — a deadlocked brain that still pongs (V6): the operator's lever is a plain SIGKILL of the brain pid, which the split makes an ordinary, session-safe strike-and-respawn (decision-table row; the pid is in the process table or the SIGUSR1 dump, since every RPC — `daemon.health` included — hangs in this state).
- **Signals to the holder** (S7 — the original draft cited a brain shutdown path that does not exist; the daemon has no SIGTERM handler and today's `systemctl stop` kills sessions via process-death PTY teardown): SIGTERM/SIGINT → forward SIGTERM to the brain (which gains a handler: persist + exit); wait bounded (10s); then **the holder SIGKILLs every remaining session child via its canonical pidfds, reaps them, unlinks the custodied socket, and exits** — the holder, not the brain, is the stop-everything executor, because children that ignore the HUP from PTY teardown must not outlive the supervisor. `systemctl stop cm-daemon` keeps meaning "stop everything". SIGHUP → logged and ignored (config reload is `daemon.reload_config`; `daemon.health` exposes the brain pid). SIGUSR1 → status line to the log; SIGUSR2 → held-down retry (above).
- **OOM posture (S11 — corrected):** `oom_score_adj` is *inherited* across fork/exec, so a unit-level `OOMScoreAdjust=-500` would protect the entire tree including the biggest consumers — inverting the intent. Spec: the unit sets `OOMScoreAdjust=-500` (holder); the holder writes `oom_score_adj = 0` for the brain and for every session child immediately after each fork (raising another same-UID process's score is unprivileged-legal; raise-only). Locally (TUI-launched, no privilege to lower) the holder inherits 0 and its natural smallness is the protection — documented as best-effort, not load-bearing.
- **Diagnostics with a dead brain**: the holder answers nothing on the control socket (it never speaks that protocol); connects hang in backlog (§ Listeners) — clients must timeout. The log file + `SIGUSR1` status dumps + process table are the operator surface; `HELD_DOWN` recovery needs only a fixed binary on disk.

**TUI-launch parity (O12), concretely.** `ensure_daemon_at_startup` launches `cm-holder` **only when explicitly configured** (`CM_HOLDER_BINARY` env or a `holder_binary` config key) — never inferred from sibling-binary presence, so building the workspace cannot flip a host into the split before its soak (O12a). The `SO_PEERCRED` staleness check (`warn_if_daemon_binary_stale`) is retargeted: post-split the listen-caller pid names the *first brain generation* and may be dead — the check is replaced by `daemon.health {holder_build_id, brain_build_id}` comparison with a connect+request timeout, whose timeout branch reports "daemon unhealthy (holder may be holding a dead brain)" rather than relaunching over a live holder (O12b/c). The launch detach discipline (`setsid`, stdio redirect, waiter thread) transfers to the holder unchanged.

**Transition guard (O13), landing before any host migrates:** today's `scripts/cm-redeploy` pgrep-matches `release/cm-daemon$` — post-split that is the *brain*; the script would SIGKILL it (a breaker strike + silent revert to the old pin) and then race a fresh monolith against the custodied listener (`AddrInUse`), reporting failure while the holder serves the old brain. cm-redeploy gains a `daemon.health.split` probe as its first step and refuses the legacy kill path on a split host; this ships in phase 3, with the dev flag, not in the rollout phase.

## Brain deploys (the new `daemon.restart`) and holder upgrades

**Brain deploy** — the everyday path, and the payoff of the whole design: `cm-redeploy` builds, then calls `daemon.restart`. Contract (O8): the brain preflights the new binary (`--verify-handoff`-style subprocess), pins it, sends `restart_brain`, and **replies `ok` to the caller before quiescing** — unlike re-exec (where success IS the exec and no reply is possible), the accepted-and-armed reply can be written before the brain exits; the connection then dies with the brain, so completion is still verify-based (recipe below), the reply only distinguishing "refused" from "in progress". Then: quiesce (the `RestartCoordinator` barrier — mutation counter, writer/delivery safe points, reader-gate freeze so no bytes die on reader stacks), a checked fsync persistence pass, `exit(0)`. The holder reaps it, execs the pinned FD (demoting the old pin to "previous"), and the new brain boots. **Mandated boot order in split mode (O16): hello → adopt → start readers per session as each record lands → arm → exit-event drain → THEN the MCP preflight and logic-state rebuild → serve.** Kernel PTY buffers are ~64 KiB; readers must precede the seconds-long python preflight, which today runs before session restore (`lib.rs` order) — a free reordering the split makes mandatory.

**cm-redeploy verification recipe (O8):** assert `daemon.health.brain_build_id == expected` **and** `brain_restarts` delta == 0 over a ≥90s inline soak (boot + one full watchdog cycle) — a single successful poll can precede a slow crash whose auto-rollback silently reverts `brain_build_id` after the script printed success. The inline soak cannot cover the breaker's 10-minute stability horizon (V1), so the script also prints the definitive all-clear condition — `breaker_state == RUNNING` with the stability timer expired — for the operator or a monitor to confirm, rather than blocking on it. Downtime honesty: control-plane unavailability = old-brain quiesce + exit + new-brain boot-to-serve; sessions stall at most; the *target* is single-digit seconds, to be measured (not asserted) in phase 6.

**Bad-but-alive brain:** the breaker keys on exits and cannot see a brain that boots and misbehaves. `daemon.rollback_brain` (strong-operator → the `rollback_brain` verb) execs the previous pin on demand (O9) — without it the operator would have to rebuild the old binary, because the deploy overwrote the path (the reason R7 exists).

**Holder upgrade** — rare by design, and where re-exec earns permanence: the holder upgrades by **re-exec'ing itself** with the sealed FD manifest, exactly the DESIGN_SEAMLESS_RESTART mechanism, applied to a process whose entire state is the manifest's natural content. The brain drives it: `daemon.upgrade_holder {path}` (strong-operator) → brain preflights the new holder binary, passes the pinned FD via a `reexec_holder` verb → holder quiesces (trivially — it pauses its loop) and writes the **holder-upgrade manifest** — a third schema variant whose field set is the holder's full state enumeration (§ The holder): per-session records incl. `incarnation`/`reap_armed`/`cgroup_path`/`last_signal_request` and held-zombie markers, the pending exit-event queue, custodied listeners, brain pid/pidfd/socketpair end/`epoch`, both brain pins, breaker state, and the **incarnation high-water mark** (V3 — a post-upgrade holder must never re-mint a previously-issued `(uid, incarnation)`; the brain's idempotency keys depend on it) — then execs. The brain stays up (children survive a parent's exec); the new holder image opens with an unsolicited re-`hello` over the manifest-carried socketpair end — the one exception to brain-sends-first — and the brain re-negotiates. Crash-class exposure during a holder exec exists exactly as in re-exec — accepted: tiny image, a few times a year. **Skew gate (S15):** "the previous pin by construction overlapped" is only true against the holder that pinned it — a holder upgrade that advances `proto_min` can strand *both* brain pins into `proto_mismatch` → `HELD_DOWN`. Therefore `daemon.upgrade_holder` refuses unless the new holder still negotiates with the **current previous pin** (checked by preflight), and the skew matrix carries a {new holder × previous-pin brain} cell.

**Operator-auth prerequisite (O10):** `daemon.restart` / `rollback_brain` / `upgrade_holder` / `migrate_split` / `split_rollback` are strong-operator, which **fails closed when `CM_OPERATOR_TOKEN` is unset** (`operator.rs:195`). The holder receives the token in its launch environment and the brain inherits it automatically (child of the holder) — respawns keep working. But cm-manager's unit sets no token today (validation is off there), and cm-redeploy sends a placeholder that only works because of that: **adding `Environment=CM_OPERATOR_TOKEN=…` to the unit (and teaching cm-redeploy to read it) is a rollout prerequisite, listed in phase 7's runbook — the migration RPC is unreachable without it.**

## Live migration: monolith → split, zero session loss

The running single-process daemon becomes the holder — its children cannot be re-parented, so the process that owns them must *become* the process that keeps them. The re-exec machinery is the vehicle:

1. Deploy `cm-holder` + the split-capable `cm-daemon` (brain) binaries.
2. Operator calls `daemon.migrate_split {holder_path, brain_path}` (strong-operator, fail-closed).
3. The old daemon pins **both** binaries by FD, preflights **both** (O14: the holder image via `--verify-handoff`-style dry run, **and** the brain binary via its own preflight — the brain is the component that will crash-loop with no previous pin if broken), and creates the brain socketpair.
4. Quiesce: the full re-exec barrier — `restart_coordinator::begin` → `wait_quiesced` → reap-gate + reader-gate freezes → checked fsync persistence pass.
5. Spawn the brain (from its pinned FD) with one socketpair end. The brain boots **parked**: it `hello`s and waits for `adopt`. Parked contract (O14): exit on channel EOF (a monolith crash between here and step 7 must not leak an invisible orphan), and exit if `adopt` isn't answerable within 60s.
6. Build the sealed manifest — **migration schema** (a versioned extension, honestly a schema project, S5): the standard session records *plus* new validated roles for the socketpair end, the **brain's pid + pidfd** (without which the holder image cannot supervise, heartbeat, reap, or roll back the brain it is about to be parent of — omitted in the original draft), the two brain pins, the custodied-listener records, and `rollback_schema_version` = the old daemon's own `MANIFEST_SCHEMA_VERSION` (see step-9 rollback). `validate_fd_roles` grows the matching probes.
7. CLOEXEC audit + allowlist-clear, signal-mask bracket, `execveat` the pinned **holder** FD. Same PID: children keep their parent, systemd sees nothing, the listener stays bound (it transfers into custody).
8. The holder image detects `CM_REEXEC_MANIFEST_FD`, validates (sealed-memfd code + new roles), builds its records (pidfd-alive + starttime cross-checks; an exited child → exit event queued, not adopted), and answers the parked brain's `adopt`. The brain adopts, rebuilds logic state from the step-4 snapshot, receives the custodied listeners, serves. `daemon.health` reports `{split: true, holder_build_id, brain_build_id, epoch}`; cm-redeploy asserts session-count continuity.
9. **Failure handling.** Pre-exec: abort exactly as re-exec aborts (guard drop un-drains; the parked brain is killed and reaped; nothing happened). Post-exec, holder-image validation failure → rollback to the pinned monolith — but **not by passing the migration manifest back** (S5: the sealed migration-schema memfd is unmodifiable and the monolith would refuse its schema, landing in the deliberate-kill terminal fallback — the exact opposite of "sessions intact"): the holder image **writes a fresh manifest at `rollback_schema_version`** (the proto crate's serializer must support emitting prior schema versions — a named deliverable with its own skew test), kills+reaps the parked brain first (it holds a channel end; EOF-exit is the backstop), and execs the rollback pin. The monolith rehydrates via its own re-exec path, sessions intact. Post-exec crash-class in the holder image → today's crash; one bounded exposure per host, once, after sandbox soak. Brain-fails-after-holder-commits → § Supervision (no previous pin ⇒ `HELD_DOWN` with path-retry; `daemon.split_rollback` remains available once any brain runs).

**Reverse migration** (escape hatch): `daemon.split_rollback {monolith_path}` → the brain **re-pins the monolith from the path at rollback time and preflights it** (O3: the migration-time pin ages — months later it is stale against state the current brain wrote; the fresh pin + `--verify-handoff` is the real contract, with the old pin as emergency fallback), sends the `split_rollback` verb with the pinned FD, quiesces, exits; the holder (armed pin = the marker, V4) writes a standard-schema manifest of its sessions and execs the monolith pin → single-process daemon again. Holder→monolith and monolith→holder are the same maneuver in opposite directions because the manifest is the shared language. **Consequence for the crate plan (O3):** the monolith spawn/reap path is **retained, runtime-selected — not deleted** — the monolith image must remain a buildable, current mode of the same crate for as long as `split_rollback` is promised. Deleting it is a future decision that must be recorded here as revoking that promise.

## Failure classes, exhaustively

| Failure | Re-exec world (best case pre-split) | Split world |
|---|---|---|
| Brain/daemon **recoverable** error on deploy | Rollback exec of pinned old binary | Same, minus the exec: breaker reverts to previous pin |
| Brain/daemon **crash-class** failure (segfault/OOM/abort), deploy or steady-state | **All sessions die** (R1) | Sessions live; ≤ 8 KiB per session of *display* bytes on reader stacks lost from fanout/scrollback (transcripts are child-written and unaffected); at most one half-written prompt per session mid-`write_all`; control plane blips seconds; unacked exit events redeliver |
| Brain wedge (hang, not crash) | External watchdog / operator | Holder heartbeat / outbound-queue rule → SIGKILL → respawn (breaker strike) |
| Bad brain deploy that crash-loops | Terminal fallback: deliberate kill + resume | Automatic rollback to previous pin; no previous → `HELD_DOWN` + path-retry (fix binary on disk = self-heal); sessions untouched throughout |
| Bad-but-alive brain | Operator rebuild + redeploy | `daemon.rollback_brain` → previous pin |
| Environmental crash loop (both pins fail: corrupt state file, API down) | Terminal fallback | `HELD_DOWN`; sessions stall but live; recovery = fix the environment or binary, no kill required |
| Cap kill during a brain gap | n/a (no gap) | Kernel hard cap enforces; attribution best-effort (`memory_events_snapshot`), may tombstone as natural exit — named residual |
| Holder crash | n/a (no holder) | **Everything dies** — today's daemon crash. Children get SIGHUP from PTY teardown; next start runs legacy restore from H1-pinned stamps. Mitigation is frozenness + OOM posture; honestly not elimination |
| Holder upgrade crash-class | n/a | Same residual as re-exec, on a tiny/rare image |
| Migration exec crash-class | — | One bounded exposure per host, once |
| Machine reboot | Children die; startup-restore | Unchanged |

## What survives vs. what blips (across a brain restart)

| Plane | Across brain restart |
|---|---|
| Session children, mid-turn work, background children | Untouched — never signaled (structurally: inert Drop + verb-only kills) |
| PTY byte streams | Planned restart: lossless (reader-gate quiesce, kernel buffers the rest). Crash: ≤ 8 KiB/session display loss (reader stacks), stall-not-loss for everything after |
| Fanout ring / scrollback, byte offsets | Lost/reset — same as re-exec; attach clients treat the generation bump as a new stream |
| Control socket | No unbind (holder custody); connects queue in backlog during the gap (clients timeout, § Listeners) |

## Security posture

- The holder has **no reachable surface**: no filesystem socket, no control protocol, no env trust (migration manifest validated + scrubbed via the sealed-memfd path). Its only peers are the process that spawned it (via manifest) and the brain it spawned (via socketpair).
- `daemon.migrate_split`, `daemon.upgrade_holder`, `daemon.split_rollback`, `daemon.rollback_brain` are **strong-operator, fail-closed** (`require_strong_operator`) — code-replacement class (R14 discipline). The token-provisioning prerequisite is § Brain deploys (O10).
- `restart_brain`/`rollback_brain`/`reexec_holder` are not RPCs — they exist only on the channel, and only the brain holds a channel end.
- Binary pins are FDs everywhere (spawn, rollback, upgrade, path-retry re-pins); no pathname is ever trusted after its open (R7, uniformly applied — `HELD_DOWN`'s path retry re-opens and re-pins, it never execs a path).
- Environment: § Environment is the contract (complete spec env, holder `env_clear`, holder environ reaches nothing). `env_sanitize` runs brain-side each generation; the holder never inherits identity into sessions by construction, with a canary guard test.

## Version-skew testing (first-class deliverable)

The permanent tax of the split is the holder⇄brain compat matrix; it is paid in CI, not in incidents:

- **Matrix axes**: {holder @ oldest-supported tag, holder @ HEAD} × {brain @ oldest-supported tag, brain @ HEAD}, **plus {holder @ HEAD × brain @ previous-pin tag}** (S15 — the rollback pair a holder upgrade must not strand). "Oldest-supported" starts as the first shipped holder tag and advances only with an explicit deprecation note here. The **new-brain × old-holder** cell is the load-bearing one — it is the steady state forever.
- **Harness**: CI builds both binaries at both refs (shared cargo target-dir keeps this cheap), runs the e2e suite over each pairing in the sandbox discipline (own-process, `env_clear`, tempdir HOME/`CM_DAEMON_SOCKET`, slow-binary wrappers for timing determinism).
- **Skew suite**: hello negotiation (incl. deliberate no-overlap → breaker → rollback); spawn/arm/exit/ack round-trips; unknown-verb + unknown-field tolerance (a canary field in every message type); exit-event redelivery across a brain SIGKILL; checkpoint round-trip; listener custody round-trip; SCM_RIGHTS law violations (frame-without-FDs, MSG_CTRUNC, unexpected FDs) hitting the specified handling (O15); prior-schema rollback-manifest emission (S5) — this cell lands with the phase-7 serializer, when the suite grows to cover it (V9).
- **Proto-crate guards**: no `deny_unknown_fields` (source-scan test); `PROTO_VERSION` bumps require a matrix-entry update (version-literal cross-check test); no brain-side session-pidfd signaling outside the holder client (S2's guard); `MSG_CMSG_CLOEXEC` on every receive path (scan test).
- **Behavioral e2e (single-version)**: spawn-through-holder parity vs. today (env — incl. the holder-environ canary, cwd, winsize, cgroup scope, controlling tty); fast-exit spawn (`/bin/false`) → correct tombstone, no stuck session (S4's race, now a regression test); brain SIGKILL mid-typescript → adopt → PTY continuity after the ≤8 KiB gap; brain SIGKILL between `kill_session` and exit → attribution survives via echo; brain failure mid-adopt → children alive (inert-Drop proof, S2); crash-loop → previous-pin rollback; both-pins-fail → `HELD_DOWN` → fix-binary-on-disk self-heal (O1); wedge → heartbeat kill; slow-but-alive brain under state-lock convoy NOT killed (S9); `user_scope_capable`-through-holder (S8); migration e2e (real monolith with live bash + claude-shaped sessions → `migrate_split` → same-PID holder, sessions verified interactive); migration-failure rollback (fresh rollback manifest path, S5); reverse migration; holder self-re-exec.

## Crate boundaries

- **`holder/`** (new workspace member) — bin `cm-holder`, lib `cm_holder` for loop unit tests. The frozen process. Depends on `cm-holder-proto` + `libc`/`nix`/`portable-pty`/`serde`/`serde_json`/`sha2`.
- **`holder-proto/`** (new) — crate `cm-holder-proto`: channel frames + verbs, SCM_RIGHTS send/recv helpers (the O15 law lives here), version constants/negotiation, and the **relocated `reexec_manifest` module** (shared language between monolith image, holder image, and brain; moved behind `pub use` re-exports so daemon code and tests compile unchanged) including prior-version serialization (S5). This crate is the compat surface; additive-only discipline lives here.
- **`daemon/`** — the brain. The fork/exec+`waitid` innards go behind a spawn-backend seam (`HolderClient` vs the retained in-process backend — **both kept, runtime-selected**, per O3's reverse-migration promise); everything else stays. Session objects gain the inert-Drop split mode (S2).
- **`tui/`** — `daemon_launch.rs`: explicit-config holder launch, health-based staleness, connect timeouts (§ Supervision, O12).

## Risks

- **The holder becomes load-bearing and wrong.** A holder bug is a fleet-wide session killer with a slow upgrade path. Bounded by: minimal LOC, single-threaded nonblocking loop, no policy, portable-pty parity spawn, the behavioral e2e suite, soak-before-cm-manager.
- **Protocol drift.** Bounded by the proto crate's additive-only discipline + the skew matrix as a merge gate; the socketpair design keeps the surface cold (no data plane).
- **Brain-boot latency is the availability story.** Bounded by the mandated boot order (readers before preflight, O16); the preflight itself is brain-internal and optimizable anytime.
- **Half-typed prompts on brain crash** (R10 residual, crash case only). Detectable by the respawned brain (delivery verification exists in the monitor stack); documented, not eliminated.
- **Cap-kill attribution gap during brain downtime** (S6 residual). Best-effort snapshot; named in § Exit provenance.
- **The retained monolith mode rots.** O3's promise means the in-process backend must stay tested: the existing daemon suite keeps running against it (it is the default until rollout), and post-rollout it remains in CI until this doc records the promise revoked.
- **Two processes to reason about.** The § Operator decision table is the design's answer; if operating the split is not *simpler* than today's table, the split has failed a design goal.
