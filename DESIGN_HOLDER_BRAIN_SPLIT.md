Implementation is **double-gated**; state as of 2026-08-19:

Consequence: **phase 1 (proto extraction — a zero-behavior refactor, safe regardless of gates) is authorized; phases 2+ remain the operator's per-phase go/no-go.** Re-exec already survives every deploy of a working binary and every recoverable rehydrate failure; this split exists solely to remove re-exec's structural residual (review finding R1).

## Trigger and goal

DESIGN_SEAMLESS_RESTART's Goal section, verbatim: "A **crash-class** failure in the new image — segfault, abort, OOM-kill, panic-with-abort, an uncaught early exit — cannot execute any rollback path: the process dies, the PTY masters and listener close with it, and the children are lost. … it cannot be engineered away inside a single process. If unconditional survival of a bad binary ever becomes a requirement, the holder/brain split stops being optional."

This document is that split. The structural observation (same doc, "Why this exists"): **the code that churns is brain-level** (auth, RPC, monitors, workflows, config, policy) **while the PTY layer it shares a process with is stable and owns the durable things** (child processes, master FDs). The split puts the durable things in a process that never changes:

- **cm-holder** — tiny, near-frozen, single-threaded. Parent of every session child and of the brain. Owns: fork/exec of session children, the canonical PTY master FDs, the spawn-time pidfds, exit reaping (`waitid` is parent-only — the one duty that *cannot* live anywhere else), kill-attribution echo, custody of the control-socket listener FDs, and supervision of the brain (respawn with backoff + one-deep pinned-binary rollback + a path-retry recovery input).
- **cm-daemon (the brain)** — everything else, i.e. today's daemon minus the fork/exec+reap innards. Restarts freely; crashes freely. On every start it re-adopts the live sessions from the holder over an inherited socketpair via SCM_RIGHTS FD passing, using the same non-killing adoption path re-exec built (`adopt::SessionCandidate` → `DaemonSession::build_adopted` → `AdoptedSessionBuild::arm`), with **inert-Drop** session objects (§ Kill authority).

Headline properties the split buys (none of which re-exec can provide):

| Property | Mechanism |
|---|---|
| A crashing brain kills no session | Holder keeps canonical masters + pidfds; brain-side session objects cannot signal on Drop (§ Kill authority); brain respawned by holder |
| A brain deploy that segfaults on start **rolls back automatically** | Holder keeps a one-deep pinned-FD history of brain binaries; the breaker (§ Supervision) execs the previous pin; hold-down re-pins from the on-disk path so a fixed binary self-heals (O1) |
| Double-brain / double-reader is structurally excluded | Inherited socketpair (no named socket); holder spawns the next brain only after the previous brain *process* has exited; plus the mandatory FD-hygiene rules of § The channel (S10 — kernel guarantee *and* stated discipline, not either alone) |
| Exit statuses survive brain downtime | Holder consumes `waitid(P_PIDFD)` under per-session authorization (`arm_reap`), queues exit events (bounded by live sessions — overflow structurally impossible), redelivers until acked |
| Kill attribution survives brain death | Attribution rides in the `signal` verb and is echoed back in the exit event — the holder remembers who asked even if the asker died; routing rule in § Exit provenance (O4) |

## Out of scope

- **Machine reboots** — children die with the machine; startup-restore + H1-pinned resume stays the answer.
- **TUI-owned session rows** (`DaemonState::tui_sessions` snapshots) — TUI-process-resident PTYs never survived daemon restarts and are untouched here.
- **Holder crash survivability.** The holder crashing is exactly today's daemon crash: every PTY dies. The mitigation is frozenness (small, single-threaded, no policy, near-zero churn) plus OOM posture (§ Supervision), not another layer of indirection. Stated as the design's honest residual, the way R1 was for re-exec. "Everything dies" is *made* true, not assumed (C5 — Linux does not kill children on parent death): the brain sets `PR_SET_PDEATHSIG(SIGKILL)` at startup (with the getppid re-check for the parent-died-before-prctl race), and holder-channel EOF is fatal for **every** brain, steady-state included, not just the parked migration brain — otherwise an orphaned brain survives holding listener + master dups while a supervisor launches a fresh holder over it.
- **Multi-host / remote transport changes.** `hosts.toml`, ssh tunnels, TUI attach — all talk to the control socket, which the brain serves exactly as today.
- **The MCP server, planning API, dispatch/cloud lane** — untouched; they speak to the control socket.

## Environment composition (S1)

portable-pty's `CommandBuilder::new` snapshots the **constructing process's** environ (`get_base_env()`; applied via `env_clear` + re-apply in `as_command`). Today's "composed env" is therefore CM_\* deltas over the daemon's inherited environment — PATH, HOME, SHELL, TERM, LANG, `XDG_RUNTIME_DIR`, `DBUS_SESSION_BUS_ADDRESS` all reach sessions only by daemon-environ inheritance, and `systemd-run --user` depends on exactly those. The original draft's "session env comes fully from the spawn spec" was false as stated. The corrected contract:

- **The brain composes a *complete* environment** into every spawn spec: a snapshot of the brain's own post-`env_sanitize` environ (the brain runs `scrub_inherited_session_env()` at startup as today, `lib.rs:343`), overlaid with the per-session CM_\* composition (`methods.rs:653-731`) and the existing secret scrubs (`session.rs:1473-1500`, relocated into spec composition).
- **The holder applies the spec exactly**: `CommandBuilder` + `env_clear()` + set precisely the spec's map. The holder's environ reaches **no session, ever** — it is not a default, not a base layer, nothing.
- The brain's environ is inherited from the holder (the holder spawns it), which inherited from systemd/the TUI — so the effective base is the same as today's daemon environ, sanitized at each brain start. A holder launched from inside a hosted claude session (the 2026-08-18 incident class) carries the poison in *its* environ for its lifetime, but every brain generation scrubs before composing, and the holder's environ never reaches a session — the leak class stays closed without the holder running scrub logic itself.
- Guard test: a canary var set in the holder's environ (and NOT in the spec) must be absent from a spawned session's `/proc/<pid>/environ`.

## Kill authority (S2)

`DaemonSession::Drop` today SIGKILLs its child via pidfd (`session.rs:3160`), and `pidfd_send_signal` works from any same-UID dup-holder — so a brain that adopts the fleet and then fails during its own startup (bind error, config error, panic-unwind reaching the registry) would SIGKILL every child the split exists to protect. Therefore, structurally:

- **Brain-side session objects have no kill-on-drop.** In split mode, `DaemonSession`'s Drop closes fds and touches nothing else — the `SessionCandidate` property (`adopt.rs`: "drop closes its own fds and never signals") extends through promotion for the session's whole brain-side life. A brain crash or unwind, at any point, closes dups and nothing more.
- **Kills are verb-only.** Every deliberate kill path — `kill_session`, the `mark_subtask_done` sweep, drain/shutdown kills, workflow fresh-context respawns, spawn-failure aborts — routes the holder (`signal` / `abort_spawn`). `DaemonSession::kill()` becomes a client call, not a syscall.
- The brain's pidfd dup exists for **observation only**: exit-ready polling (`poll_pidfd_until_exit_ready` works from a non-parent) and identity cross-checks. A source-scan guard test (the repo's guard-test idiom) asserts no brain-side `pidfd_send_signal`/`kill(2)` call sites against session pidfds outside the holder client. (The memory-cap watcher's victim kills target arbitrary in-cgroup PIDs — usually grandchildren the holder has no record of — and stay brain-direct; see § Watcher placement.)

This is a real semantic change to the adoption path — on main the two-stage `DaemonSession::build_adopted` → `AdoptedSessionBuild::arm` (`session.rs:2306/2183`), whose contract today deliberately gives adopted sessions "the pidfd-SIGKILL Drop"; the split does not reuse that clause, and the types gain a split-mode paragraph in phase 3.

## The holder

A single-threaded event loop over `poll(2)`: the brain socketpair end, one pidfd per session child, the brain's pidfd, and a timerfd (watchdog/backoff timers). No threads, no async runtime, no state lock — there is nothing to lock. An exit-ready pidfd of an **un-armed** record is masked out of the poll set with its readiness latched (V7 — an exited child's pidfd is level-triggered readable and would otherwise spin the loop at 100% CPU during the spawn-to-arm window); `arm_reap` unmasks it straight into the `waitid` path.

**Nonblocking IO, mandatorily (S3).** The channel is `O_NONBLOCK` in both directions holder-side, with a bounded in-holder outbound queue. The holder never issues a blocking `write()` — a brain whose channel-consumer stops draining (state-lock convoy, wedged persist) would otherwise wedge the *holder's* loop, including the very watchdog meant to catch it. Rule: outbound queue full beyond a threshold for longer than the wedge horizon ⇒ the brain **is** wedged (same consequence as missed pongs: SIGKILL + respawn + breaker strike). The loop's only other latency is `spawn`'s fork/exec round-trip — bounded milliseconds, stated as the loop's latency budget.

**Holder-resident state, in full** (per session): `{uid, incarnation, generation_meta, child_pid, child_start_time, canonical_master: OwnedFd, canonical_pidfd: OwnedFd, reap_armed: bool, cgroup_prefix: Option<String>, cgroup_path: Option<String> (set at arm, V5), watcher_checkpoint: Option<serde_json::Value>, last_signal_request: Option<{sig, attribution, at}>, spawned_at}` — a superset-compatible sibling of `reexec_manifest::SessionRecord` (`reexec_manifest.rs:243`), because the migration writes one into the other (§ Live migration). **`incarnation` is a holder-minted monotonic u64, and it — never the brain's `generation` — keys every verb and event** (O2: `generation` in this codebase is the transcript-rotation counter, bumped by /clear//compact and *reused* across revive — the exact wrong identity; it rides the record as opaque `generation_meta` for the brain's benefit only. The manifest doc-comment drift this review flagged is FIXED on main: `SessionRecord.generation` is now documented as the transcript-rotation counter with process identity explicitly reserved for a separate field — this design's incarnation (`reexec_manifest.rs:246`)). Plus: the exit-event queue (bounded by live sessions — a session exits at most once per incarnation, so overflow is structurally impossible; the original draft's lossy-ring language is deleted, S12/O7), custodied listener FDs (§ Listeners), the current + previous pinned brain-binary FDs + the `--brain` path for hold-down re-pinning (O1), the brain's pid/pidfd/socketpair/`epoch`, and the breaker state (§ Supervision). **`epoch`** (O18c) is the holder's brain-spawn counter — it names the brain generation in `hello`, `status`, and logs. The holder persists **nothing to disk** except its own log; all durable state is brain-side. If the holder dies, everything dies — disk-durability inside the holder buys nothing.

**What the holder must never contain** (the frozenness contract, enforceable at review time): config parsing beyond argv, the control wire protocol, auth of any kind, JSON-RPC dispatch, planning/API clients, transcript or task or workflow or workspace concepts, policy of any kind (cap sizes, protected sets, idle rules, victim selection), PTY byte handling, socket binding, disk persistence. One narrow carve-out, explicit (S6): at `waitid` time, if the record has a stored cgroup path (delivered on `arm_reap`, V5), the holder does a single best-effort read of `<path>/memory.events` into the exit event — a mechanical file read, no interpretation. A holder change is a design-doc-noted event that must run the full skew matrix (§ Version-skew testing). LOC budget: ~1,500–2,500 including the protocol server side.

**Dependencies**: `libc`, `nix`, `portable-pty` (spawn parity — see below), `serde`/`serde_json` (protocol + manifest payloads), `sha2` (sealed-manifest checksum on the migration path). No `anyhow`, no `toml`, no clients.

**Spawn parity**: the holder spawns via `portable_pty::native_pty_system().openpty(...)` + `slave.spawn_command(...)` — the exact primitive `PendingSession::spawn` uses today (`session.rs:1453-1560`) — then extracts and keeps the raw master fd and pidfd. Reusing the battle-tested path keeps child-side semantics (session leader, controlling tty, slave closed in parent, `close_random_fds` in the child pre-exec — verified: portable-pty's own pre_exec scrubs fds > 2, so holder-fd hygiene toward sessions is structurally covered) bit-identical to today. portable-pty's `Child` is a bare `std::process::Child` whose Drop neither kills nor waits (verified against the vendored source) — the holder drops it and owns the child via pidfd alone, as today's reaper does. `openpty`/`spawn_command` spawn no helper threads — compatible with the single-threaded loop.

**Bootstrap**: argv only — `cm-holder --brain <path> --log-file <path>`; on the migration path, `CM_REEXEC_MANIFEST_FD` (validated by the same sealed-memfd code, then scrubbed). No `--socket-path`, no `--tls`: the holder binds nothing (§ Listeners). `setrlimit(NOFILE, 65536)` at start (2 FDs per session × `MAX_SESSIONS` 4096 ≈ 8k, plus headroom); **the brain raises its own NOFILE equally at startup** (O15 — it holds 2+ dups per session plus its normal load).

## The channel: an inherited socketpair, never a named socket

The holder⇄brain channel is a `socketpair(AF_UNIX, SOCK_STREAM)` created by whoever spawns the brain, with one end inherited by the brain as a known FD. There is **no named holder socket on the filesystem, ever**. Consequences:

- **Unforgeable.** Hosted sessions run as the same UID; a named 0600 holder socket would hand every hosted agent a spawn-arbitrary-argv / signal-any-session / take-any-session's-FDs surface, gated only by another token scheme. An inherited socketpair has no path to connect to — the attack surface does not exist.
- **Exactly one brain — kernel guarantee *plus* stated discipline (S10).** The holder spawns the next brain only after `waitid` on the previous brain's pidfd returns, and **closes its old socketpair end at that moment** (killing any SCM_RIGHTS dups still in flight inside the dead channel's buffer). Process exit closes every FD the old brain itself held. The residual channel: FDs a brain-forked *transient* child (git, python preflight) inherited and outlived the brain with. Closing that channel is brain-side protocol law: **every SCM_RIGHTS receive uses `MSG_CMSG_CLOEXEC`**, and every brain-held session/listener/channel FD is CLOEXEC from birth (`F_DUPFD_CLOEXEC` throughout, as today's `session.rs:2913` / `adopt.rs` already do). With those two rules — enforced by a proto-crate scan test and a skew-suite canary — an orphaned transient child can hold no session FD, and double-reader is excluded.
- **Survives the migration exec.** During live migration the *brain exists before the holder* (§ Live migration): the old daemon creates the socketpair, spawns the brain with one end, and carries the other end across its own exec into the holder image via the re-exec manifest. A socketpair end is just an FD; the manifest already knows how to escort FDs across an exec.

**Framing and SCM_RIGHTS law (O15, C7)**: length-prefixed JSON frames with a hard **maximum frame length (1 MiB, the `MAX_MANIFEST_BYTES` discipline; the shipped control wire rejects oversized prefixes before allocation — `control/wire.rs` — and the channel does the same on both sides)**; a length violation is protocol-fatal with the same handling as `MSG_CTRUNC` below. **Request/reply envelope (C7)**: every brain→holder request carries a monotonic `req_id`; replies echo it, so concurrent in-flight calls (spawn + signal + checkpoint from different brain threads over the one stream) route correctly — the `HolderClient` serializes *writes*, pipelines requests, and matches replies by id. Unsolicited holder→brain frames (`exit_event`, `ping`, the post-upgrade re-`hello`) carry no `req_id`; their acking is by their own keys. FD-bearing frames follow strict conventions, each with a skew-suite test: (1) one `sendmsg` per FD-bearing frame, ancillary data attached to that frame's first byte, never coalesced with other frames' bytes in the same `sendmsg`; (2) receivers always supply a control buffer sized for the frame type's declared FD count (max 2) and always pass `MSG_CMSG_CLOEXEC`; (3) a frame that promises FDs arriving without them, or with `MSG_CTRUNC` — protocol violation: the brain treats it as fatal and exits (respawn is cheap and safe); the holder treats it as a brain failure (close channel, SIGKILL, breaker strike); (4) unexpected FDs on a non-FD frame are closed immediately, never stored.

**Version negotiation**: the brain always sends first — `hello {proto_min, proto_max, brain_build_id}`; the holder replies `{proto: chosen, holder_build_id, holder_proto_min, holder_proto_max, epoch, session_count}` (no deadlock: writer roles are fixed, and both sides' first read is bounded by a handshake timeout; the parked migration brain's first read is instead bounded by O14's 60s adopt deadline, which supersedes the generic timeout — its hello reply legitimately waits out the monolith's manifest-build + exec + validation, V8). No overlap → brain logs loudly and exits with a distinct code the holder recognizes as `proto_mismatch` (counts toward the breaker → previous-pin rollback, which is only *usually* sufficient — see the S15 gate in § Holder upgrades). Within a major version: unknown JSON fields are ignored on both sides (`deny_unknown_fields` is banned in the proto crate — enforced by a source-scan test); an unknown verb gets a typed `unsupported_verb` reply, never a disconnect.

## Protocol verbs

| Verb | Direction | FDs | Semantics |
|---|---|---|---|
| `hello` | brain→holder, then reply | — | Version negotiation (above) |
| `spawn {uid, generation_meta, argv, env, cwd, cols, rows, cgroup_prefix?}` | brain→holder | reply: `[master_dup, pidfd_dup]` | openpty + fork/exec (env applied via `env_clear` + exact spec map, § Environment) + `pidfd_open` + starttime capture. Reply `{incarnation, pid, child_start_time}` + the two dups. Typed errors (`openpty_failed`, `exec_failed{errno}`, `uid_exists{incarnation}`). The child is **not reap-armed yet** |
| `arm_reap {uid, incarnation, cgroup_path?}` | brain→holder | — | Sent under the brain's state lock immediately after registry insert — the protocol descendant of `arm_reaper`-under-lock (`methods.rs:968`) and of the reap gate. Before arming, an exited child is **held as a zombie** (no `waitid`): its `/proc/<pid>` stays readable for the brain's post-spawn cgroup discovery and starttime cross-checks (preserving the zombie-parking property `reexec.rs:1354` documents), and no exit event exists to race the insert (S4). Carries the brain's *discovered* cgroup path (V5 — spawn-time `cgroup_prefix` is caller metadata, not the scope path, which only exists post-spawn via `/proc/<pid>/cgroup` discovery, `methods.rs:799`); the holder stores it for the § The holder carve-out read. After arming: exit-ready → `waitid` → `exit_event` |
| `adopt` | brain→holder | per record reply: `[master_dup, pidfd_dup]` | The re-adopt handshake, sent by every brain at startup after `hello`: one `adopt_record` frame per holder-resident session — `{uid, incarnation, generation_meta, child_pid, child_start_time, cgroup_prefix, watcher_checkpoint, last_signal_request, reap_armed}` — each with fresh dups; then `adopt_listeners` (§ Listeners); then `adopt_done {exit_events_pending}`. Re-arming is **not automatic** (C9 — the holder cannot know the brain has built and inserted a record): the brain re-arms each adopted record with the ordinary `arm_reap` after its registry insert, exactly as the spawn path does, and exit events (pending or new) for a record deliver only once it is armed. Adopt records carry `reaped: bool`. Reconciliation, three rules: live records unknown to the brain's disk snapshot are adopted with minimal meta and flagged `orphan_adopted` (surfaced via `list_sessions`) — never silently killed; records in the snapshot but absent holder-side are resolved against the pending exit events, else tombstoned `status_lost` (§ Exit provenance); a **reaped** record with no pending exit event (the ack→forget crash window, V2 — the exit was already acked and tombstoned, `forget` never sent) is answered with `forget` during reconciliation, not adopted (after a `status_lost` tombstone in the corruption case where the snapshot has no trace of it either). The third rule is also what bounds holder *record* growth — events are bounded by live sessions, records by forget-at-reconciliation |
| `signal {uid, incarnation, sig, attribution}` | brain→holder | — | Ordering (C13): the holder first checks its own exit knowledge — record reaped, exit event pending, or pidfd already exit-ready (a zero-timeout poll; `pidfd_send_signal` "succeeds" against a zombie, so success alone cannot mean pre-exit delivery) → reply `already_exited {exited_at?}` and **stamp nothing** (S16); otherwise `pidfd_send_signal`, then stamp `last_signal_request` on success. Residual: an exit landing between the poll check and the signal is stamped — a microsecond ambiguity today's stamp-first code shares (`methods.rs:1804` stamps, ignores ESRCH) |
| `abort_spawn {uid, incarnation}` | brain→holder | — | The `PendingSession`-abort translation (S4/O6): SIGKILL via canonical pidfd, `waitid` unconditionally (armed or not), drop the record, emit **no** exit event. For spawns the brain is abandoning pre-insert |
| `update_checkpoint {uid, incarnation, watcher_checkpoint}` | brain→holder | — | Overwrites the opaque checkpoint blob (rare: protected-set finalization, `last_high` bump per breach) |
| `forget {uid, incarnation}` | brain→holder | — | Post-exit GC only: **refused (`not_exited`) while the child is unreaped** (S4/O6 — the original spec leaked permanent holder-side zombies). After the exit event is acked and tombstoned, drops the canonical FDs and the record |
| `exit_event {uid, incarnation, code, signal, exited_at, last_signal_request, memory_events_snapshot?}` | holder→brain | — | Emitted at `waitid` (post-arm). `exited_at` is the holder's clock. `memory_events_snapshot` is the § The holder carve-out read. Queued until acked; redelivered on brain reconnect. Idempotent brain-side, keyed `(uid, incarnation)` — which requires a **durable** commit key (C4): in split mode `ExitedTombstone` gains `incarnation`, and a redelivered event whose key matches an on-disk tombstone is already-processed → ack + `forget`, never parked. By construction (arming happens post-insert) an event's uid is always registry-resolvable; an event for an unknown uid is a protocol anomaly the brain logs and parks — never ack-and-drop (S4) |
| `ack_exit {uid, incarnation}` | brain→holder | — | Sent only after `handle_session_exit` has run a **checked** tombstone persistence (the 4c sidecar's checked/fsync write — best-effort session persistence is not an ack basis, C4); a failed write means no ack, and redelivery retries a now-replay-tolerant handler. Holder prunes the event (the record itself lives until `forget`) |
| `store_listener {kind: unix\|tls, meta}` | brain→holder | `[listener_fd]` | Listener custody (§ Listeners): replaces any stored listener of that kind (holder closes the old one). `meta` carries the socket path for shutdown-unlink |
| `restart_brain {}` | brain→holder | `[pinned_new_brain_fd]` | The deploy verb (§ Brain deploys). **Arm-late rule (C8)**: the brain sends this only AFTER its quiesce + checked persistence have fully succeeded — nothing fallible may sit between arming and exit, or an unrelated later crash triggers the armed deploy. Holder stores the pinned FD as "next", replies `ok`; the brain exits; the holder execs the pin. Auto-disarm: brain still alive 30s after arming → holder disarms and logs; `cancel_pending` disarms explicitly |
| `rollback_brain {}` | brain→holder | — | Exec the **previous** pinned brain (O9): the operator's answer to a bad-but-not-crashing brain, exposed as `daemon.rollback_brain` (strong-operator). Same arm-late + auto-disarm rules as `restart_brain` |
| `cancel_pending {}` | brain→holder | — | Disarm any armed `restart_brain` / `rollback_brain` / `split_rollback` pin (C8) — the abort path when something fails between arming and exit |
| `reexec_holder {}` | brain→holder | `[pinned_new_holder_fd]` | Holder upgrade (§ Holder upgrades; V4): holder replies `ok`, pauses its loop, writes the holder-upgrade manifest, and execs the pinned FD; the brain survives and re-negotiates over the surviving socketpair |
| `rollback_record {uid, incarnation, record}` | brain→holder | — | Reverse-migration prelude (C1): one opaque, fully-populated `SessionRecord` payload (at `rollback_schema_version`) per live session, composed by the brain — which alone holds the logic meta (title, engine, bindings, perms, caps, activity, done-report) the shipped record shape requires. The holder stores the blobs unparsed; at manifest-write time it fills in exactly the fd-number/pid fields it owns. Frozenness intact: the holder never interprets the blob |
| `split_rollback {}` | brain→holder | `[pinned_monolith_fd]` | Reverse migration (§ Live migration; V4). Preconditions the holder enforces (C2): every exit event acked, every reaped record forgotten, and a `rollback_record` present for every remaining live record — otherwise `not_drained`, because a consumed `waitid` status is unrepresentable in a standard manifest and would be lost to the monolith. Same arm-late rule as `restart_brain` (C8): sent only after quiesce + drain + records transferred. Holder **arms** the monolith pin, replies `ok`; the brain exits; the holder — the armed pin IS the exit marker; no exit-code magic — writes a fresh standard-schema manifest (records = the stored blobs + its fd/pid fields) and execs the monolith pin instead of respawning a brain |
| `status` | brain→holder | — | `{sessions, pending_exit_events, epoch, brain_restarts, breaker_state, holder_build_id}` — surfaced through `daemon.health` |
| `ping` / `pong` | holder→brain / brain→holder | — | Wedge watchdog. **`pong` is answered on the brain's channel-reader thread and touches no lock** (S9) — a slow-but-alive brain (state-lock convoy) must not be indistinguishable from a wedged one; conversely a channel-reader that can't answer *is* the wedge the watchdog exists for |

### Why write / resize / read are NOT verbs

The task sketch listed `write`/`resize` in the holder's verb set. This design deliberately removes them: the brain receives master-FD **dups** at spawn/adopt and performs PTY reads (`gated_reader_loop` on a further `F_DUPFD_CLOEXEC` dup, exactly as today), writes (`SessionWriter` writes on the dup; `write_and_stamp_operator`, prompt-delivery threads — all unchanged), and resizes (`TIOCSWINSZ` acts on the terminal; any fd of the master works) directly. Because:

- **The data plane must not cross the IPC boundary.** Attach streams shovel PTY bytes at interactive rates; verb-mediating them doubles copies, adds a hop of latency to every keystroke, and — worst — makes the holder protocol *hot*: a busy, high-frequency surface is exactly what accumulates churn pressure, and holder churn is the one thing this design must prevent. With dups, the holder's steady-state message rate is ~zero (exit events + rare checkpoints + 30s pings).
- **It's already proven.** `AdoptedMasterPty` (`adopt.rs:105`) runs the full `MasterPty` surface honestly over a bare inherited fd — including the writer-drop-VEOF suppression and on-demand `tty_name` (review-verified, incl. EIO→EOF on a master dup after child exit and `TIOCSWINSZ`-on-dup). Re-exec's rehydrate already runs sessions on adopted fds; the split makes adoption the *only* path.
- **Crash semantics are exactly right for free.** Brain dies → its dups close → the canonical master in the holder keeps the PTY's open file description alive (no SIGHUP to the child — review-verified); nobody reads → the kernel buffer (~64 KiB) fills → a chatty child blocks on write. A stall, never loss. The new brain adopts and its readers drain the backlog.

The one write-path caveat: a brain that dies **mid-`write_all`** of a multi-byte paste leaves a partial prompt in the child's input buffer — the R10 problem, now unfixable-by-barrier for *crashes* (planned restarts still quiesce writers via the coordinator). Honest position: a crash-class brain failure can leave one session with a half-typed prompt (visible, recoverable by a human or by the respawned brain's delivery verification); it cannot corrupt state or lose the session. Recorded in the failure table.

### Spawn path, before/after

Today's `start_session_with_spawn_fn` ordering (`methods.rs:444`) survives with one substitution. Brain-side, unchanged: cap validation, workspace resolve, worktree serialization queues, `claude_trust::maybe_pretrust_for_spawn` (a `~/.claude.json` write — happens before the verb), kill-log baseline capture (`reaper::capture_baseline_for_spawn`), argv composition including the `systemd-run` wrap, and now *full* env composition (§ Environment). Then, instead of `PendingSession::spawn` forking in-process: the `spawn` verb → holder forks → reply `{incarnation, pid, child_start_time}` + 2 dups → brain builds a `SessionCandidate` from the dups → cgroup discovery from `/proc/<pid>/cgroup` (`path::discover_session_cgroup_path` — plain /proc reads, valid even for a fast-exited child because the un-armed holder holds it as a zombie), watcher spawn, then the existing lock-held tail: uid recheck → promote → `DaemonSession::build_adopted` → `AdoptedSessionBuild::arm` (inert-Drop variant, § Kill authority; arms the brain-side reader + exit observer) → registry insert → **`arm_reap`** → persist → `ManifestDiff::Added`. Failure anywhere pre-insert → `abort_spawn`. **Spawn and crash-recovery become the same code path** — every brain-side session is an adopted session.

Reconciliation seams (S4): a brain that dies between the holder's fork and its own persist leaves a holder record the next brain's snapshot lacks → adopted as `orphan_adopted` (operator disposes; sessions are user-owned, never auto-killed). A retried spawn hitting `uid_exists{incarnation}` resolves against that record: adopt it or `abort_spawn` it, explicitly — never spawn a twin.

The brain-side "reaper" thread becomes an **exit observer**: the pidfd-poll half of `gated_reaper_body` (`poll_pidfd_until_exit_ready`) is unchanged — pidfd polling works from a non-parent — but the consume step (`consume_exit_status`'s `waitid`, parent-only, would `ECHILD`) is replaced by "await the holder's `exit_event` for authoritative status". The reap gate (`reap_gate.rs`) is succeeded by `arm_reap` + the ack protocol for brain restarts (an unacked status is redelivered, never lost) and remains only inside the holder's own re-exec path (§ Holder upgrades).

## Listeners: brain binds, holder custodies (O11)

The holder must hold listener FDs across brain restarts (no connection-refused window) — but binding is policy-adjacent (stale-socket probe, atomic-0600 umask dance in `bind_socket`, `lib.rs:195`; `[tls]` config in `daemon.toml`) and belongs in the brain. Resolution: **the brain performs every bind; the holder is a custodian.**

- Fresh start: holder boots with no listeners; the first brain binds the Unix socket (existing `bind_socket`, unchanged, in the daemon crate) and the TLS listener when configured, then `store_listener`s each FD with the holder. The socket file appears when the first brain is up — the TUI's launch probe already polls with a timeout.
- Brain restart: `adopt_listeners` returns dups of the custodied FDs; the brain skips binding. `SO_REUSE`-style races are impossible — the listening socket is the same open file description across generations.
- Rebind (config change): **at the next brain start** (deploys are routine): the boot-time brain compares stored-listener meta against its config; on mismatch it binds the new and `store_listener`s it (holder closes the old). Hot rebind via `daemon.reload_config` stays out of scope, matching shipped behavior — TLS is deliberately startup-only (`methods.rs:3392`) and `TlsAcceptor::serve` consumes its listener in a process-lifetime accept loop with no cancellation handle (`control/tls.rs:193`), a loop that conveniently dies with the old brain at exactly the boundary where rebinding happens (C12).
- Shutdown: the holder unlinks the stored Unix socket path (from `store_listener.meta`) on exit, best-effort; the next bind's stale-probe still covers a crash.
- Diagnostics honesty (S14/O12): during a brain gap, `connect()` on the custodied listener **succeeds into the backlog and hangs** — it does not refuse. Clients (TUI, MCP, health probes) must use connect+request timeouts and treat them as "daemon unhealthy", not "daemon absent"; the TUI change is specified in § Supervision.

## Exit provenance over IPC

The fidelity requirement: today's tombstone/attribution semantics (`handle_session_exit`, `methods.rs:1161`) must survive the boundary — `killed`/`killed_by`/`exited_at` on tombstones, `memory_cap_kill` classification, `status="reported"` carry-over, monitor fire messages quoting kill provenance.

- **The kernel status** (`code`, `signal`) is consumed by the holder at `waitid` time and stamped with the holder's clock (`exited_at` fidelity across brain downtime — the brain uses the event's timestamp, not its receipt time).
- **Attribution routing rule (O4), explicit:** every kill that records attribution today — `kill_session` (`methods.rs:1810`, `"operator"`/caller uid), the `mark_subtask_done` sweep (`methods.rs:14505`, `"<uid> (mark_subtask_done)"`), drain/shutdown kills — **must route the `signal` verb**; a guard test asserts no attributed kill path signals a session pidfd directly. Echo-less by design: `abort_spawn` (pre-registry, nothing to attribute) and inert Drop (signals nothing, § Kill authority). The brain keeps `DaemonState::record_kill_request` exactly as today *and* the holder echoes `last_signal_request` in the exit event, so `handle_session_exit`'s merge gains one source: explicit kill request (brain state) → holder echo (survives brain death) → memory-cap classification → unattributed. A brain that died between `kill_session` and the exit event no longer loses the `killed_by` — strictly better than today, and it closes for brain restarts the one gap the shipped re-exec's phase-4e state-inventory audit left open (**gap 5**: `kill_requests` + `LastExitProbe.operator_kill_requested` are in-memory and unserialized, so a SIGKILL whose exit wasn't reaped pre-freeze loses attribution across a re-exec — the holder echo is exactly that fact made durable).
- **`LastExitProbe` correlation is unchanged in shape**: `set_kernel` is fed by the exit-event consumer instead of an in-process reaper; the lazy consume-time kill-log scan (`reaper::build_last_exit_since` against the spawn-time baseline) still classifies watcher kills. The attach `End` frame's bounded spin on `kernel_set` (`stream.rs:543`) still closes the reader-EOF-vs-status race — now reader-EOF (brain) vs exit-event arrival (holder), same ≤1s bound, same degradation shape (review-verified).
- **Cap kills during brain downtime (S6), honestly:** the kernel enforces the hard cap regardless (`MemoryMax` lives in the cgroup), but `is_cap_kill` (`reaper.rs:119`) returns false without a kill-log record, and the dead brain wrote none; the scope's `memory.events` is torn down with the scope. Mitigation: the holder's carve-out `memory_events_snapshot` read at `waitid` time (best-effort — it can lose the teardown race), which the brain's classifier accepts as cap evidence (new, additive input to the existing lazy classification). **Residual, named:** a hard-cap OOM kill during a brain gap whose snapshot read lost the race is tombstoned as a natural signal-9 exit — the truncated-tail-as-final-report UX bug can recur in exactly that window. Accepted; the alternative (a policy-bearing holder) costs more than the window is worth.
- **Exit events are bounded by live sessions** (one per incarnation), so the queue cannot overflow; the original lossy-ring semantics are deleted (S12/O7). The one residual "no status" case — a brain snapshot names a session the holder has neither a record nor an event for (e.g. holder restarted via upgrade while the session was already `forget`-eligible) — tombstones as `status_lost: true` with `killed=false`, no code/signal, `exited_at` = detection time: a new honest tombstone field, surfaced like `killed` is today.

## Memory-cap watcher placement

**Decision: the watcher loop stays brain-side; its policy state checkpoints into the holder.** This is no longer speculative: re-exec's phase 4d shipped the checkpoint mechanism (`session_watch::WatcherCheckpoint`, carried opaquely in `SessionRecord.watcher_checkpoint`, `reexec_manifest.rs:347`) with capture at safe points, re-adoption seeding, and loud fresh-policy reset on a missing/unparseable blob — the holder simply becomes where the blob lives between brain generations. Shape: `{protected: [(pid, starttime)...], last_high, cgroup_path, kills_file_offset_baseline}` — protected entries are **(pid, starttime) pairs**, not bare PIDs (S13 — **landed on main**: `WATCHER_CHECKPOINT_VERSION` 2 upgraded the entries to pairs, crediting this review; a v1 blob fails the version gate into the loud fresh-policy reset). Written via `update_checkpoint` when it changes — rare — with ordering rules (C11): the finalized protected set is sent **before enforcement begins** (so a brain crash can never leave enforcement having run against a set the holder never saw, which on re-adopt would recompute protection around a runaway fork), and a `last_high` bump is sent **before** the corresponding breach action (channel delivery is in-order; the kill-log record dedupes attribution if the action itself replays). Residual, named: a crash between the watcher's local publication and the holder processing the frame re-runs at most one breach evaluation or triggers the loud fresh-policy reset — never a silent divergent policy. A respawned brain re-adopts and resumes the same policy instead of recomputing from the live cgroup — recomputing would rebuild `protected` from *current* `cgroup.procs`, which after a runaway fork would protect the very hog the cap exists to kill.

During brain downtime there is **no soft-cap enforcement** (no watcher); the kernel-enforced hard cap is the backstop, and the attribution residual for that window is stated in § Exit provenance. The watcher's victim kills (highest-RSS non-protected in-cgroup PID — usually a grandchild the holder has no record of) remain brain-direct signals with their own starttime+cgroup re-verification (`session_watch.rs` `mod kill`), outside the holder verb set by design.

**Capability probing (S8, resolved per C10):** `mcp_config::user_scope_capable` today runs `systemd-run --user --scope … /bin/true` *in the daemon's own environ*; the S8 worry was that a brain-side probe validates a different environment than the holder-side real spawns. The § Environment contract dissolves it: session env is a fully-specified map applied via `env_clear`, identical whichever process forks — so the probe stays **brain-side** but runs under the exact spec-env discipline (`env_clear` + the same composed map a real capped spawn's spec would carry), which keeps its exit-status/stderr needs (`mcp_config.rs:892`) out of the holder and avoids abusing the session `spawn` lifecycle (an ordinary spawn's `abort_spawn` emits no exit event and `arm_reap` wants a registry-resolvable session — the probe is neither). A dedicated bounded `probe_spawn` holder verb remains the additive fallback if brain-vs-holder divergence is ever actually observed.

**Alternative considered and rejected — holder-side enforcement loop**: moving `run_watcher`'s poll/breach/kill loop into the holder keeps soft-cap enforcement alive during brain downtime. Rejected because it moves policy (victim selection, protected-set semantics, grace timing, kill-record shape — `session_watch.rs` is 1,900 lines with three behavioral revisions) into the frozen process, for a window the kernel hard cap already bounds. If soft-cap-during-outage ever matters, the verb surface admits it later (`install_watch {spec}`) — additive, per the protocol rules.

## Supervision topology

**One external supervisor, one supervised binary: the holder.** systemd on cm-manager (`cm-daemon.service`'s `ExecStart` becomes `/opt/cm-daemon/cm-holder --brain /opt/cm-daemon/cm-daemon`, `Restart=always` now guarding only holder crashes); the TUI locally. **The brain is never a systemd unit and never TUI-launched** — the holder is its parent, always.

**Brain lifecycle and the breaker (O1/O5/O9), fully specified.** The holder pins brain binaries by FD at exec time (`open` + `fexecve`, R7 — a mid-deploy `cp` can never half-apply) and keeps `{current, previous}` pins plus the `--brain` *path*. Every brain couples its life to the holder's (C5): it sets `PR_SET_PDEATHSIG(SIGKILL)` at startup (then re-checks `getppid()` for the parent-died-first race) and treats channel EOF as fatal — a holder crash therefore kills the brain too, keeping "holder crash = everything dies" true and making a stale orphaned brain (still holding listener + master dups under a freshly launched holder) impossible. States:

| State | In it because | Exits it via |
|---|---|---|
| `RUNNING` | brain alive, hello'd | brain exit → `BACKOFF`; `restart_brain`/`rollback_brain` → exec next/previous pin |
| `BACKOFF` | brain exited | respawn current pin after backoff (0.5s → 30s cap). **Crash counter**: trips → `ROLLBACK` at 3 *consecutive* exits with no intervening stable run — deliberately un-windowed (V1: a 60s window never trips on a slow loop crashing every minute or two, which would flap forever); a **stable run** (10 min with hello + adopt completed + no exit) resets the counter |
| `ROLLBACK` | breaker tripped | exec the **previous** pin; the failed pin is **discarded, not demoted** — the pair cannot ping-pong (O5). No previous pin (first post-migration brain, or already consumed) → `HELD_DOWN`. Previous also trips the breaker → `HELD_DOWN` |
| `HELD_DOWN` | no pin works | every 60s: **re-open `--brain` from the path, fresh pin, try it** (O1) — an operator who fixes the binary on disk self-heals the fleet with no channel and no signal; `SIGUSR2` forces an immediate retry. Each attempt logged. Sessions ride it out indefinitely (they stall at worst) |

Environmental crash loops (corrupt `daemon-sessions.json`, API down at boot) crash *both* pins — the path-retry input is what makes `HELD_DOWN` recoverable without killing the holder, which was the original spec's only exit (O1: committing the exact fleet-kill the design exists to prevent).

- **Wedge watchdog**: `ping` every 30s; 3 misses (90s) → SIGKILL the brain, respawn, breaker strike. `pong` is lock-free by spec (S9); outbound-queue-not-draining is the same wedge (S3). The lock-free pong deliberately leaves one class invisible — a deadlocked brain that still pongs (V6): the operator's lever is a plain SIGKILL of the brain pid, which the split makes an ordinary, session-safe strike-and-respawn (decision-table row; the pid is in the process table or the SIGUSR1 dump, since every RPC — `daemon.health` included — hangs in this state).
- **Signals to the holder** (S7 — the original draft cited a brain shutdown path that does not exist; the daemon has no SIGTERM handler and today's `systemctl stop` kills sessions via process-death PTY teardown): SIGTERM/SIGINT → forward SIGTERM to the brain (which gains a handler: persist + exit); wait bounded (10s); then **the holder SIGKILLs every remaining session child via its canonical pidfds, reaps them, unlinks the custodied socket, and exits** — the holder, not the brain, is the stop-everything executor, because children that ignore the HUP from PTY teardown must not outlive the supervisor. `systemctl stop cm-daemon` keeps meaning "stop everything". SIGHUP → logged and ignored (config reload is `daemon.reload_config`; `daemon.health` exposes the brain pid). SIGUSR1 → status line to the log; SIGUSR2 → held-down retry (above).
- **OOM posture (S11 — corrected):** `oom_score_adj` is *inherited* across fork/exec, so a unit-level `OOMScoreAdjust=-500` would protect the entire tree including the biggest consumers — inverting the intent. Spec: the unit sets `OOMScoreAdjust=-500` (holder); the holder writes `oom_score_adj = 0` for the brain and for every session child immediately after each fork (raising another same-UID process's score is unprivileged-legal; raise-only). Locally (TUI-launched, no privilege to lower) the holder inherits 0 and its natural smallness is the protection — documented as best-effort, not load-bearing.
- **Diagnostics with a dead brain**: the holder answers nothing on the control socket (it never speaks that protocol); connects hang in backlog (§ Listeners) — clients must timeout. The log file + `SIGUSR1` status dumps + process table are the operator surface; `HELD_DOWN` recovery needs only a fixed binary on disk.

**TUI-launch parity (O12), concretely.** `ensure_daemon_at_startup` launches `cm-holder` **only when explicitly configured** (`CM_HOLDER_BINARY` env or a `holder_binary` config key) — never inferred from sibling-binary presence, so building the workspace cannot flip a host into the split before its soak (O12a). The `SO_PEERCRED` staleness check (`warn_if_daemon_binary_stale`) is retargeted: post-split the listen-caller pid names the *first brain generation* and may be dead — the check is replaced by `daemon.health {holder_build_id, brain_build_id}` comparison with a connect+request timeout, whose timeout branch reports "daemon unhealthy (holder may be holding a dead brain)" rather than relaunching over a live holder (O12b/c). The launch detach discipline (`setsid`, stdio redirect, waiter thread) transfers to the holder unchanged.

**Transition guard (O13), landing before any host migrates:** today's `scripts/cm-redeploy` pgrep-matches `release/cm-daemon$` — post-split that is the *brain*; the script would SIGKILL it (a breaker strike + silent revert to the old pin) and then race a fresh monolith against the custodied listener (`AddrInUse`), reporting failure while the holder serves the old brain. cm-redeploy gains a `daemon.health.split` probe as its first step and refuses the legacy kill path on a split host; this ships in phase 3, with the dev flag, not in the rollout phase.

## Brain deploys (the new `daemon.restart`) and holder upgrades

**Brain deploy** — the everyday path, and the payoff of the whole design: `cm-redeploy` builds, then calls `daemon.restart`. Contract (O8, ordering per C8's arm-late rule): the brain preflights the new binary (`--verify-handoff`-style subprocess), pins it, and **replies `accepted` to the caller** — unlike re-exec (where success IS the exec and no reply is possible), the reply can be written before the brain exits; the connection then dies with the brain, so completion is still verify-based (recipe below), the reply only distinguishing "refused" from "in progress". Then: quiesce (the `RestartCoordinator` barrier — mutation counter, writer/delivery safe points via `writer_gate`, reader-gate freeze so no bytes die on reader stacks), the checked fsync persistence pass, and **only after all of that succeeds**, `restart_brain` with the pinned FD, then `exit(0)` — arming and exit are adjacent, with nothing fallible between (a quiesce/persist failure aborts with `cancel_pending` and un-drains, leaving no armed pin to fire on a later unrelated crash). The holder reaps it, execs the pinned FD (demoting the old pin to "previous"), and the new brain boots. **Mandated boot order in split mode (O16): hello → adopt → start readers per session as each record lands → arm → exit-event drain → THEN the MCP preflight and logic-state rebuild → serve.** Kernel PTY buffers are ~64 KiB; readers must precede the seconds-long python preflight, which today runs before session restore (`lib.rs` order) — a free reordering the split makes mandatory.

**cm-redeploy verification recipe (O8):** assert `daemon.health.build_id == expected` (the brain's compile-time identity — the key is `build_id`, phase 7 review F12 aligned this text with the wire) **and** `brain_restarts` delta == 0 over a ≥90s inline soak (boot + one full watchdog cycle) — a single successful poll can precede a slow crash whose auto-rollback silently reverts `brain_build_id` after the script printed success. The inline soak cannot cover the breaker's 10-minute stability horizon (V1), so the script also prints the definitive all-clear condition — `breaker_state == RUNNING` with the stability timer expired — for the operator or a monitor to confirm, rather than blocking on it. Downtime honesty: control-plane unavailability = old-brain quiesce + exit + new-brain boot-to-serve; sessions stall at most; the *target* is single-digit seconds, to be measured (not asserted) in phase 6.

**Bad-but-alive brain:** the breaker keys on exits and cannot see a brain that boots and misbehaves. `daemon.rollback_brain` (strong-operator → the `rollback_brain` verb) execs the previous pin on demand (O9) — without it the operator would have to rebuild the old binary, because the deploy overwrote the path (the reason R7 exists).

**Holder upgrade** — rare by design, and where re-exec earns permanence (S15 gate as implemented, phase 7 + review F3: the candidate holder's proto range must COVER the **running holder's advertised range** from the hello reply — every pin this lineage ever accepted negotiated inside it, so coverage implies no pin strands; the residual is a lineage whose holder range ever NARROWS, which is a deprecation event that must advance the oldest-supported note + matrix baseline instead of riding an upgrade): the holder upgrades by **re-exec'ing itself** with the sealed FD manifest, exactly the DESIGN_SEAMLESS_RESTART mechanism, applied to a process whose entire state is the manifest's natural content. The brain drives it: `daemon.upgrade_holder {path}` (strong-operator) → brain preflights the new holder binary, passes the pinned FD via a `reexec_holder` verb → holder quiesces (trivially — it pauses its loop) and writes the **holder-upgrade manifest** — a third schema variant whose field set is the holder's full state enumeration (§ The holder): per-session records incl. `incarnation`/`reap_armed`/`cgroup_path`/`last_signal_request` and held-zombie markers, the pending exit-event queue, custodied listeners, brain pid/pidfd/socketpair end/`epoch`, both brain pins, breaker state, and the **incarnation high-water mark** (V3 — a post-upgrade holder must never re-mint a previously-issued `(uid, incarnation)`; the brain's idempotency keys depend on it) — then execs. The brain stays up (children survive a parent's exec); the new holder image opens with an unsolicited re-`hello` over the manifest-carried socketpair end — the one exception to brain-sends-first — and the brain re-negotiates. Crash-class exposure during a holder exec exists exactly as in re-exec — accepted: tiny image, a few times a year. **Skew gate (S15):** "the previous pin by construction overlapped" is only true against the holder that pinned it — a holder upgrade that advances `proto_min` can strand *both* brain pins into `proto_mismatch` → `HELD_DOWN`. Therefore `daemon.upgrade_holder` refuses unless the new holder still negotiates with the **current previous pin** (checked by preflight), and the skew matrix carries a {new holder × previous-pin brain} cell.

**Operator-auth prerequisite (O10):** `daemon.restart` / `rollback_brain` / `upgrade_holder` / `migrate_split` / `split_rollback` are strong-operator, which **fails closed when `CM_OPERATOR_TOKEN` is unset** (`operator.rs:195`). The holder receives the token in its launch environment and the brain inherits it automatically (child of the holder) — respawns keep working. But cm-manager's unit sets no token today (validation is off there), and cm-redeploy sends a placeholder that only works because of that: **adding `Environment=CM_OPERATOR_TOKEN=…` to the unit (and teaching cm-redeploy to read it) is a rollout prerequisite, listed in phase 7's runbook — the migration RPC is unreachable without it.**

## Live migration: monolith → split, zero session loss

The running single-process daemon becomes the holder — its children cannot be re-parented, so the process that owns them must *become* the process that keeps them. The re-exec machinery is the vehicle:

1. Deploy `cm-holder` + the split-capable `cm-daemon` (brain) binaries, **and flip the external supervisor's launch mode first** (C6): update the systemd unit's `ExecStart` to the holder (cm-manager) / set the TUI's explicit holder config (local) *before* the RPC, so a crash or reboot at any later point relaunches the intended topology — without the flip, the next restart silently reverts to a monolith over the migrated state. (Reverse migration requires the inverse flip, ordered the same way.)
2. Operator calls `daemon.migrate_split {holder_path, brain_path}` (strong-operator, fail-closed).
3. The old daemon pins **both** binaries by FD, preflights **both** (O14: the holder image via `--verify-handoff`-style dry run, **and** the brain binary via its own preflight — the brain is the component that will crash-loop with no previous pin if broken), and creates the brain socketpair.
4. Quiesce: the full re-exec barrier — `restart_coordinator::begin` → `wait_quiesced` → reap-gate + reader-gate freezes → checked fsync persistence pass.
5. Spawn the brain (from its pinned FD) with one socketpair end. The brain boots **parked**: it `hello`s and waits for `adopt`. Parked contract (O14): exit on channel EOF (a monolith crash between here and step 7 must not leak an invisible orphan), and exit if `adopt` isn't answerable within 60s.
6. Build the sealed manifest — **migration schema v4, extending the shipped v3** (v3 = full session records + `reexec_generation`; honestly a schema project, S5): the standard session records *plus* new validated roles for the socketpair end, the **brain's pid + pidfd** (without which the holder image cannot supervise, heartbeat, reap, or roll back the brain it is about to be parent of — omitted in the original draft), the two brain pins, the custodied-listener records, and `rollback_schema_version` = the old daemon's own `MANIFEST_SCHEMA_VERSION` (see step-9 rollback). `validate_fd_roles` grows the matching probes. TLS caveat: the shipped `daemon.restart` **refuses `[tls]`-configured daemons** (listener handoff unimplemented — CLAUDE.md decision table); `migrate_split` inherits that refusal until the TLS-listener manifest role lands here — post-split, custody covers TLS with no further manifest work (the brain binds and stores it).
7. CLOEXEC audit + allowlist-clear, signal-mask bracket, `execveat` the pinned **holder** FD. Same PID: children keep their parent, systemd sees nothing, the listener stays bound (it transfers into custody).
8. The holder image detects `CM_REEXEC_MANIFEST_FD`, validates (sealed-memfd code + new roles), builds its records (pidfd-alive + starttime cross-checks; an exited child → exit event queued, not adopted), and answers the parked brain's `adopt`. The brain adopts, rebuilds logic state from the step-4 snapshot, receives the custodied listeners, serves. `daemon.health` reports `{split: true, holder_build_id, brain_build_id, epoch}`; cm-redeploy asserts session-count continuity.
9. **Failure handling, split by trust state (C3).** Pre-exec: abort exactly as re-exec aborts (guard drop un-drains; the parked brain is killed and reaped; nothing happened). Post-exec, two classes: **(a) the migration manifest itself fails integrity/structure/role validation** → the shipped corrupt-manifest rule governs (`reexec_manifest.rs` module contract: touch NO escrow FD — a rollback pin named by a manifest you couldn't validate is not a rollback pin): boot fresh, sessions lost — a crash-class residual of the migration exec, named as such in the failure table, minimized by the manifest being written seconds earlier by the very process that validated the schema. **(b) the manifest validates but a later holder-init step fails** (record build, listener adoption, brain spawn) → rollback via the validated manifest's pins is safe: the holder image **writes a fresh manifest at `rollback_schema_version`** (the proto crate's serializer must support emitting prior schema versions — a named deliverable with its own skew test), kills+reaps the parked brain first (it holds a channel end; EOF-exit is the backstop), and execs the rollback pin. Exit statuses cannot be lost here (C2): nothing was ever armed — no brain completed adopt — so the holder image consumed no `waitid`; children that died during the attempt are still zombies whose statuses the monolith reaps itself, exactly as in re-exec. The monolith rehydrates via its own re-exec path, sessions intact. Post-exec crash-class in the holder image → today's crash; one bounded exposure per host, once, after sandbox soak. Brain-fails-after-holder-commits → § Supervision (no previous pin ⇒ `HELD_DOWN` with path-retry; `daemon.split_rollback` remains available once any brain runs).

**Reverse migration** (escape hatch): `daemon.split_rollback {monolith_path}` → the brain **re-pins the monolith from the path at rollback time and preflights it** (O3: the migration-time pin ages — months later it is stale against state the current brain wrote; the fresh pin + `--verify-handoff` is the real contract, with the old pin as emergency fallback), then quiesces, **drains** (processes + acks every pending exit event, `forget`s every reaped record — a consumed `waitid` status has no standard-manifest representation, C2), streams a `rollback_record` per live session (the fully-populated `SessionRecord` payloads only the brain can compose — the holder's own records deliberately lack the logic meta, C1), sends `split_rollback` with the pinned FD (arm-late, C8), exits; the holder (armed pin = the marker, V4; preconditions enforced as `not_drained`) writes a fresh standard-schema manifest from the stored record blobs plus its own fd/pid fields and execs the monolith pin → single-process daemon again. Holder→monolith and monolith→holder are the same maneuver in opposite directions because the manifest is the shared language. **Consequence for the crate plan (O3):** the monolith spawn/reap path is **retained, runtime-selected — not deleted** — the monolith image must remain a buildable, current mode of the same crate for as long as `split_rollback` is promised. Deleting it is a future decision that must be recorded here as revoking that promise.

## Failure classes, exhaustively

| Failure | Re-exec world (best case pre-split) | Split world |
|---|---|---|
| Brain/daemon **recoverable** error on deploy | Rollback exec of pinned old binary | Same, minus the exec: breaker reverts to previous pin |
| Brain/daemon **crash-class** failure (segfault/OOM/abort), deploy or steady-state | **All sessions die** (R1) | Sessions live; ≤ 8 KiB per session of *display* bytes on reader stacks lost from fanout/scrollback (transcripts are child-written and unaffected); at most one half-written prompt per session mid-`write_all`; control plane blips seconds; unacked exit events redeliver |
| Brain wedge (hang, not crash) | External watchdog / operator | Holder heartbeat / outbound-queue rule → SIGKILL → respawn (breaker strike) |
| Bad brain deploy that crash-loops | Terminal fallback: deliberate kill + resume | Automatic rollback to previous pin; no previous → `HELD_DOWN` + path-retry (fix binary on disk = self-heal); sessions untouched throughout |
| Bad-but-alive brain | Operator rebuild + redeploy | `daemon.rollback_brain` → previous pin |
| Environmental crash loop (both pins fail: corrupt state file, API down) | Terminal fallback | `HELD_DOWN`; sessions stall but live; recovery = fix the environment or binary, no kill required |
| Cap kill during a brain gap | n/a (no gap) | Kernel hard cap enforces; attribution best-effort (`memory_events_snapshot`), may tombstone as natural exit — named residual |
| Holder crash | n/a (no holder) | **Everything dies** — today's daemon crash: the brain is killed via `PR_SET_PDEATHSIG` + channel-EOF (C5), children get SIGHUP from PTY teardown; next start runs legacy restore from H1-pinned stamps. Mitigation is frozenness + OOM posture; honestly not elimination |
| Holder upgrade crash-class | n/a | Same residual as re-exec, on a tiny/rare image |
| Migration exec crash-class, incl. the migration manifest failing validation post-exec (its rollback pin is then untrusted by the corrupt-manifest rule, C3) | — | One bounded exposure per host, once |
| Machine reboot | Children die; startup-restore | Unchanged |

## Security posture

- The holder has **no reachable surface**: no filesystem socket, no control protocol, no env trust (migration manifest validated + scrubbed via the sealed-memfd path). Its only peers are the process that spawned it (via manifest) and the brain it spawned (via socketpair).
- `daemon.migrate_split`, `daemon.upgrade_holder`, `daemon.split_rollback`, `daemon.rollback_brain` are **strong-operator, fail-closed** (`require_strong_operator`) — code-replacement class (R14 discipline). The token-provisioning prerequisite is § Brain deploys (O10).
- `restart_brain`/`rollback_brain`/`reexec_holder` are not RPCs — they exist only on the channel, and only the brain holds a channel end.
- Binary pins are FDs everywhere (spawn, rollback, upgrade, path-retry re-pins); no pathname is ever trusted after its open (R7, uniformly applied — `HELD_DOWN`'s path retry re-opens and re-pins, it never execs a path).
- Environment: § Environment is the contract (complete spec env, holder `env_clear`, holder environ reaches nothing). `env_sanitize` runs brain-side each generation; the holder never inherits identity into sessions by construction, with a canary guard test.

## Version-skew testing (first-class deliverable)

The permanent tax of the split is the holder⇄brain compat matrix; it is paid in CI, not in incidents:

- **Matrix axes**: {holder @ oldest-supported tag, holder @ HEAD} × {brain @ oldest-supported tag, brain @ HEAD}, **plus {holder @ HEAD × brain @ previous-pin tag}** (S15 — the rollback pair a holder upgrade must not strand). "Oldest-supported" starts as the first shipped holder tag and advances only with an explicit deprecation note here. The **new-brain × old-holder** cell is the load-bearing one — it is the steady state forever. *Baseline governance, pre-ship (phase 5): until a holder ships to a real host, the pin is `924ff6a` — the first commit where a holder and a brain interoperate at all (phase 3) — set as `BASELINE_REF` in `scripts/holder-skew-matrix`; the previous-pin cell coincides with old-brain × new-holder until pins exist (phase 6).*
- **Harness**: CI builds both binaries at both refs (shared cargo target-dir keeps this cheap), runs the e2e suite over each pairing in the sandbox discipline (own-process, `env_clear`, tempdir HOME/`CM_DAEMON_SOCKET`, slow-binary wrappers for timing determinism).
- **Skew suite**: hello negotiation (incl. deliberate no-overlap → breaker → rollback); spawn/arm/exit/ack round-trips; unknown-verb + unknown-field tolerance (a canary field in every message type); exit-event redelivery across a brain SIGKILL; checkpoint round-trip; listener custody round-trip; SCM_RIGHTS law violations (frame-without-FDs, MSG_CTRUNC, unexpected FDs) hitting the specified handling (O15); prior-schema rollback-manifest emission (S5) — LANDED (phase 7): the matrix's fourth cell reverse-migrates a HEAD split into the BASELINE monolith binary (`CM_SKEW_MONOLITH_BIN`, `reverse_migration_manifest_boots_the_target_monolith`), executed green (V9).
- **Proto-crate guards**: no `deny_unknown_fields` (source-scan test); `PROTO_VERSION` bumps require a matrix-entry update (version-literal cross-check test); no brain-side session-pidfd signaling outside the holder client (S2's guard); `MSG_CMSG_CLOEXEC` on every receive path (scan test).
- **Behavioral e2e (single-version)**: spawn-through-holder parity vs. today (env — incl. the holder-environ canary, cwd, winsize, cgroup scope, controlling tty); fast-exit spawn (`/bin/false`) → correct tombstone, no stuck session (S4's race, now a regression test); brain SIGKILL mid-typescript → adopt → PTY continuity after the ≤8 KiB gap; brain SIGKILL between `kill_session` and exit → attribution survives via echo; brain failure mid-adopt → children alive (inert-Drop proof, S2); crash-loop → previous-pin rollback; both-pins-fail → `HELD_DOWN` → fix-binary-on-disk self-heal (O1); wedge → heartbeat kill; slow-but-alive brain under state-lock convoy NOT killed (S9); `user_scope_capable`-through-holder (S8); migration e2e (real monolith with live bash + claude-shaped sessions → `migrate_split` → same-PID holder, sessions verified interactive); migration-failure rollback (fresh rollback manifest path, S5); reverse migration; holder self-re-exec.

## Crate boundaries

- **`holder/`** (new workspace member) — bin `cm-holder`, lib `cm_holder` for loop unit tests. The frozen process. Depends on `cm-holder-proto` + `libc`/`nix`/`portable-pty`/`serde`/`serde_json`/`sha2`.
- **`holder-proto/`** (new) — crate `cm-holder-proto`: channel frames + verbs, SCM_RIGHTS send/recv helpers (the O15 law lives here), version constants/negotiation, and the **relocated `reexec_manifest` module** (shared language between monolith image, holder image, and brain; moved behind `pub use` re-exports so daemon code and tests compile unchanged) including prior-version serialization (S5). This crate is the compat surface; additive-only discipline lives here.
- **`daemon/`** — the brain. The fork/exec+`waitid` innards go behind a spawn-backend seam (`HolderClient` vs the retained in-process backend — **both kept, runtime-selected**, per O3's reverse-migration promise); everything else stays. Session objects gain the inert-Drop split mode (S2).
- **`tui/`** — `daemon_launch.rs`: explicit-config holder launch, health-based staleness, connect timeouts (§ Supervision, O12).

## Rollout runbook (phase 7)

Staged: **local first (TUI-launched), soak, then cm-manager** — each stage gets its own operator go. The migration is one RPC; the runbook is mostly prerequisites and verification.

### Local (TUI-supervised)

1. **Build + stage binaries**: `cargo build --release -p cm-daemon -p cm-holder`; deploy both to the served path (the same place cm-redeploy deploys `cm-daemon`). The holder binary's path must be stable — HELD_DOWN's path-retry and every future TUI launch use it.
2. **Flip the supervisor FIRST (C6)**: write the holder path into `~/.cm/holder-binary` (one line). From this moment any TUI daemon (re)launch — including after a crash or reboot mid-migration — comes up split, never a monolith over migrated state. (Env `CM_HOLDER_BINARY` remains a one-shot override; the file is the durable flip. Reverse migration = delete the file FIRST, then `daemon.split_rollback`.)
3. **Migrate**: operator RPC `daemon.migrate_split {holder_path, brain_path}` (strong-operator; the TUI's token at `~/.cm/operator-token`). The connection dies at the exec — that is the success shape.
4. **Verify** (the same fire-and-verify discipline as cm-redeploy): `daemon.health` → `split: true`, `sessions` unchanged, `holder_build_id` present, `brain_pid` a CHILD of the unchanged daemon PID (`ps -o ppid= -p <brain>`); attach to a session and type. Watch `breaker_state == running` through the 10-minute stability horizon.
5. **Soak**: run normal work through it for the agreed window (days, not minutes — the weekly `daemon.restart` deploy exercising `restart_brain` at least once is part of the soak's definition of done).
6. **Escape hatch**: delete `~/.cm/holder-binary`, then `daemon.split_rollback {monolith_path}` — sessions ride back; verify `split:false`, same PID, session count intact.

### cm-manager (systemd-supervised)

The ORDER below is load-bearing (review F6 — a crash between misordered steps either invokes a missing holder or fresh-starts a holder over the monolith instead of the same-PID handoff):

1. **Stage both binaries FIRST**: scp `cm-daemon` + `cm-holder` to `/tmp`, then `sudo install` into `/opt/cm-daemon/` (install is atomic-enough via rename semantics; verify with `--holder-preflight` / `--daemon-preflight` runs on the staged files). Nothing references the holder path until step 3, but staging first means no later step can race a missing binary.
2. **O10 token, while `ExecStart` still names the monolith**: add `Environment=CM_OPERATOR_TOKEN=<value>` to `cm-daemon.service` (validation is currently OFF there — turning the strong-operator gate ON is part of this step, not optional: `daemon.migrate_split` is code-replacement class), teach the operator tooling to read it, `systemctl daemon-reload`, then **restart the unit NOW** (`systemctl restart cm-daemon` — the ONE deliberate session-killing restart of this rollout, startup-restore resumes them) and verify `daemon.health.strong_operator_auth == true`. Doing the token restart while `ExecStart` is still the monolith is what keeps step 3 restart-free.
3. **C6 flip, WITHOUT restarting**: change `ExecStart` to `/opt/cm-daemon/cm-holder --brain /opt/cm-daemon/cm-daemon`, `systemctl daemon-reload`, and do NOT restart — the flip exists so a crash or reboot from this instant relaunches the intended topology; a manual restart here would fresh-start a holder INSTEAD of migrating.
4. **Migrate**: `daemon.migrate_split {holder_path, brain_path}` over the SSH tunnel; verify as in the local runbook (plus one codex/claude session spawn end-to-end — the daemon-side MCP path has host-specific config).

Reverse migration, same discipline inverted: flip `ExecStart` back to the monolith + `daemon-reload` (no restart), THEN `daemon.split_rollback {monolith_path}`.

### Post-migration operations (what changes day-to-day)

- `cm-redeploy` already routes `daemon.restart` through `restart_brain` in split mode (phase 6) — the weekly deploy needs no new habits; verification keys on `holder_epoch` +1 exactly.
- Holder upgrades (rare): `daemon.upgrade_holder {holder_path}` — S15-gated; verify `holder_build_id` changed while `holder_epoch` + session count did not.
- `systemctl stop` / SIGTERM to the holder = the S7 stop-everything sequence (sessions deliberately killed + socket unlinked; startup-restore resumes them later).

## Risks

- **The holder becomes load-bearing and wrong.** A holder bug is a fleet-wide session killer with a slow upgrade path. Bounded by: minimal LOC, single-threaded nonblocking loop, no policy, portable-pty parity spawn, the behavioral e2e suite, soak-before-cm-manager.
- **Protocol drift.** Bounded by the proto crate's additive-only discipline + the skew matrix as a merge gate; the socketpair design keeps the surface cold (no data plane).
- **Brain-boot latency is the availability story.** Bounded by the mandated boot order (readers before preflight, O16); the preflight itself is brain-internal and optimizable anytime.
- **Half-typed prompts on brain crash** (R10 residual, crash case only). Detectable by the respawned brain (delivery verification exists in the monitor stack); documented, not eliminated.
- **Cap-kill attribution gap during brain downtime** (S6 residual). Best-effort snapshot; named in § Exit provenance.
- **The retained monolith mode rots.** O3's promise means the in-process backend must stay tested: the existing daemon suite keeps running against it (it is the default until rollout), and post-rollout it remains in CI until this doc records the promise revoked.
- **Two processes to reason about.** The § Operator decision table is the design's answer; if operating the split is not *simpler* than today's table, the split has failed a design goal.
